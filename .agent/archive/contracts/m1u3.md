# acceptance contract — M1.u3 budgets, failure modes, cancellation

Tier = `kernel`. MAIN authors every code file in the primary tree. This contract is the
single decision surface: the red suite, review checklists and differential checks decide
against it, never against MAIN's code.

Source clause (`.agent/roadmap.md`, M1 u3):
> Stack/depth/inference/wall-clock budgets, typed error states, consult-stderr fatality,
> cooperative abort plus terminate-and-recreate.
> Accept: each limit surfaces its own typed state; hard cancel drops asserted state and
> returns a 337-document engine; malformed goals and consult `ERROR` fail closed; no
> unbounded query reaches the UI.

u2's contract (`.scratch/contract-m1u2.md`) stays in force in full. Its `P` predicates and
`I` invariants are inherited, not restated.

## D — decisions RULED by MAIN from wave-1 evidence

| id | decision | evidence |
| --- | --- | --- |
| D1 | Enforcement is **hybrid and split by capability**. Prolog owns stack, depth and inference. JS owns wall-clock, the answer cap and every hard stop. | `spike-m1u3-pl.md` `s.compose`: nesting `setup_call_cleanup(stack)→catch(stack)→inference→depth→goal` yielded distinct `stack_limit_exceeded`, `depth_limit_exceeded`, `inference_limit_exceeded`, and cleanup restored the 1073741824 B flag with 337 documents / 7 answers intact. `s.cost`: +0.346 ms, +0.30% over 30 paired runs. Against a PL-only design: `s.wallclock` — the build reports `threads=false`, `library(time)` raises `existence_error(source_sink,library(time))`, and `call_with_time_limit/2` and `alarm/4` raise procedure existence errors. |
| D2 | Prolog-side limits alone are **not** a bound on a query. A JS answer cap and a JS deadline are mandatory. | `spike-m1u3-pl.md` `s.risk`: the full stack+depth+inference wrapper let `repeat` emit 100000 `success` answers in 452.232 ms with `D=1` and `I=true`; only the probe's external cap stopped it. |
| D3 | The hard deadline lives on the **main thread**, never in the worker. | `spike-m1u3-js.md` `s.watchdog`: during a synchronous `repeat,fail` the main-thread 25 ms timer fired at 25.97 ms while the identical in-worker timer never fired across 249.80 ms. Confirmed by `spike-m1u3-pl.md` `s.wallclock`: a 10 ms worker timer fired only at 825.601 ms, after an 825.129 ms synchronous `next()` returned. |
| D4 | `solve` **yields to the worker macrotask queue between solutions**, so a `cancel` message can be received mid-query. Cooperative abort granularity = one solution step. | `spike-m1u3-pl.md` `s.abort`: a flag flipped between answers in 0.034 ms and the next iterator step returned `cooperative_cancelled`; the same flag polled inside recursion could not observe a queued timer until a 270.176 ms `next()` returned. `spike-m1u3-js.md` `s.wallclock`: real-KB maximum single `next()` = **50.11 ms across 80 sampled Node steps** — a sample maximum on that corpus, not a per-goal bound over u4's six catalog goals and not a browser measurement (M1 review R40, R44). The 62.00 ms this row carried has no source. A microtask yield does not admit messages; the yield must be a macrotask. |
| D5 | Hard cancel = `terminate()` then respawn, refetch, reload, re-verify contract. Nothing is reused but the browser HTTP cache. | `spike-m1u3-js.md` `s.terminate` (3.52 ms, spinner thread gone in 0.19 ms, post-stop CPU 0.34 ms per 200 ms), `s.recreate` (5/5 cycles schema 1 / 337 documents, 181.75–223.96 ms, median 194.82 ms, **in Node**). The shipping platform measures 526.4–1732.5 ms, median 641.6 over 5/5 browser cycles, against a 335 ms browser PVM boot floor (M1 review R41) — any UI-facing latency claim uses the browser figure. Post-termination worker CPU is measured in Node only and stays declared unmeasured in a browser, `s.residue` (338/present → 337/absent in 193.13 ms). `spike-m1u3-pl.md` `s.abort` independently measured terminate 2.745 ms and recreate 261.579 ms. |
| D6 | A runtime consult is **fail-open on its return value** and must be judged by drained diagnostics alone; on any `ERROR` the engine is discarded, not merely the request. | `spike-m1u3-pl.md` `s.consult`: syntax-error and failing-directive consults both returned `bindings success:true` and threw nothing, `on_output` captured `stderr:ERROR:` text, and `probe_before/0`, `probe_after/0` and `probe_after_directive/0` all stayed loaded — the engine is contaminated before the caller learns anything. `map-m1u3.md` `m.stderr`: `tools/kb/produce.mjs:72-96` already ships the sink-and-drain recipe. |
| D7 | Limit classification reads **decoded term structure**, never message text. Depth and inference bind their outcome atom inside a successful wrapper result; stack is caught as `error(resource_error(stack),_)` before it reaches the native exception branch. `src/engine/terms.ts` is unchanged by this unit. | `map-m1u3.md` `m.terms`: `decodeOnce` collapses native exceptions to a message-only `prolog-error` at `src/engine/terms.ts:125-129`, so text is the only thing that survives that path. `spike-m1u3-pl.md` `s.stack`: the caught term is structured `error(resource_error(stack),stack_overflow{...})`. |
| D8 | Yieldable `forEach` heartbeat plus the runtime's `abort()` is **out of scope**. Cooperative abort uses the declared iterator plus a macrotask yield. | `map-m1u3.md` `m.swipl-api`: `consult`, `load_string`, `abort` and the heartbeat methods are undeclared runtime API absent from `swipl-wasm` 8.0.7's `.d.ts`, and `abort()` is observed only by yieldable iteration. D4's solution-boundary granularity meets the accept clause at 50.11 ms worst step across 80 sampled Node steps; that sample, not a corpus bound, is what the decision rests on (M1 review R44). The kernel DOES take three undeclared `swipl-wasm` dependencies — `query[Symbol.iterator]()`, `query.close?()` and the term constructors — ruled acceptable at M1 review R26 behind an exact version pin plus the memory record; this row's earlier "no undeclared-API dependency" was false. Finer granularity is a `.agent/polish.md` entry. |
| D9 | Heap exhaustion is a **named typed state**, and it forces recreation. | `spike-m1u3-js.md` `s.memory`: runaway assertions reached 2222464 KiB peak RSS in 19.26 s and returned a typed `assertz/1: Not enough resources: no_memory` with no throw, abort or kill, while the same engine still answered all 7 category-A solutions — so the caller can be told, but asserted residue and a saturated heap remain. |

D1 scope (M1 review R37): the Prolog half is proven on the real PVM through the shipped
wrapper. The JS half was **Node-proven composition only** at u3 close — `s.watchdog` used
`worker_threads` and the committed deadline case drives a `FakeWorker`. The browser leg was
measured later at M1 review R39/R41 (1004 ms hard stop, worker terminated, replacement
booted at 337 documents) and holds; it is not in `pnpm gate`, which stays browser-free on
the `pnpm smoke` precedent.

D9 scope (M1 review R45): heap exhaustion is a typed state **in Node only**. In a browser a
runaway `assertz` loop aborts the WASM runtime after 12088 ms and reaches the client as
`{code:'prolog', message:'Aborted(). Build with -sASSERTIONS for more info.'}` — never
`limit:'heap'`, so this row's recreation path and the R09 fix that implements it are both
unreachable there. Without an explicit `reset()` the client keeps the dead worker and every
later query returns the same abort, which breaches P3.4 on the shipping platform. An explicit
`reset()` does recover: the replacement boots, reports 337 documents and drops the residue.
Reachability bounds the impact — M1 ships six bag-derived catalog goals, all bounded (max
119.972 ms, 7/5/2/1/3/12 solutions) with no free-text intake, so no shipped path reaches the
abort. Automatic recovery is `.agent/polish.md` "Browser WASM abort leaves a dead session",
gated on free-text intake.


## P — testable predicates

`MUST` = failure is a defect. Every red test, review row and check binds to one id.

### P1 budget spec
- P1.1 Every query request MUST carry a budget spec covering all four limits: stack bytes, depth, inferences, wall-clock ms. No public API may run a goal without one.
- P1.2 Each budget value MUST be validated as a finite positive safe integer before any Prolog runs. Zero, negative, fractional, non-finite, missing and over-maximum values MUST each fail as a typed protocol error.
- P1.3 Budget validation MUST happen on both sides of the boundary. The worker MUST NOT trust the client's validation.
- P1.4 The spec MUST also carry an answer cap, and the cap MUST be enforced by the JS driver, not by Prolog. [D2]

### P2 typed limit states
- P2.1 Stack exhaustion MUST surface as its own terminal state, distinct from every other limit and from a generic Prolog error.
- P2.2 Depth exhaustion MUST surface as its own terminal state.
- P2.3 Inference exhaustion MUST surface as its own terminal state.
- P2.4 Wall-clock expiry MUST surface as its own terminal state.
- P2.5 The answer cap MUST surface as its own terminal state, distinguishable from an honest exhausted run.
- P2.6 Cancellation MUST surface as its own terminal state, distinguishable from every limit.
- P2.7 Heap exhaustion MUST surface as its own terminal state. [D9] **Unit-tested by
  design, ruled at M1 review R28.** A live trip costs 19.26 s and ~2222464 KiB peak RSS
  (D9's own measurement), so it belongs in neither `pnpm gate` nor a shared-machine test
  run. Committed coverage splits the predicate in two: `readOutcome` classification on
  the decoded `no_memory` term (`tests/engine-budgets.test.ts` P2.8), and the
  terminate-and-recreate consequence under a fake worker (P2.7, the R09 fix). The live
  trip itself stays a spike measurement, never re-run in CI.
- P2.8 Classification MUST read decoded term structure. No limit may be identified by matching text in a message. [D7]
- P2.9 The limit states MUST be compiler-exhaustive: `isTerminal` and every client-side switch over outcomes MUST fail to compile when a new state is added and not handled.

### P3 budget enforcement
- P3.1 The stack flag MUST be lowered for the goal and restored on every exit path — success, failure, limit, exception and cancel. [`s.compose` cleanup restored 1073741824 B]
- P3.2 Depth and inference limits MUST compose with backtracking: a goal with several solutions MUST still yield its early solutions before a limit terminates it.
- P3.3 A budget MUST bound the whole request, including display rendering, not one solution.
- P3.4 After any budget trip the engine MUST remain sound: the same session MUST still report 337 documents at schema 1 and still answer the real category-A goal with 7 solutions. [`s.residue` both spikes]
- P3.5 A `repeat`-shaped goal MUST terminate through the answer cap or the deadline. It MUST NOT return an unbounded solution list. [D2]
- P3.6 Wall-clock MUST be enforced twice: a soft between-solutions check inside the worker that preserves the engine, and a hard main-thread deadline that terminates it. [D3]

### P4 cancellation and recreation
- P4.1 A cancel request MUST be received and acted on while a multi-solution query is running. [D4]
- P4.2 Cooperative cancel MUST target a specific in-flight request id, and MUST NOT settle any other request.
- P4.3 Cooperative cancel MUST leave the engine booted and usable; a following query MUST succeed without a reboot.
- P4.4 Hard cancel MUST terminate the worker, respawn it, and re-verify the contract out of the rebooted engine before reporting ready.
- P4.5 Hard cancel MUST drop asserted state: a `dynamic/1`-declared overlay clause visible before the cancel MUST be absent after it, while the engine still reports 337 documents. [roadmap accept clause; `s.residue`]
- P4.6 Every request in flight at a hard cancel MUST settle exactly once with a typed cause. No pending promise may survive, and no unhandled rejection may occur. [inherits u2 P2.3, P2.5]
- P4.7 A request issued during the respawn window MUST settle typed rather than hang or attach to a dead worker.
- P4.8 Request ids MUST stay monotonic across worker generations. A response from a dead generation MUST NOT settle a request belonging to a live one.
- P4.9 Hard cancel MUST be single-flight: concurrent triggers MUST produce one termination and one respawn.
- P4.10 Every watchdog timer MUST be cleared on each terminal outcome. A settled request MUST leave no armed timer.
- P4.11 `dispose()` MUST stay terminal with no respawn. Hard cancel MUST be a separate awaitable lifecycle operation. `_PL_halt` MUST NOT be used for either.

### P5 fail-closed inputs
- P5.1 A malformed goal MUST fail as a typed Prolog error through the existing parse guard and MUST NOT execute. [u2's guard]
- P5.2 An honest zero-solution goal MUST stay `failure`, distinguishable from every limit and from a malformed goal.
- P5.3 A runtime consult MUST capture stderr through both `printErr` and `on_output`, drain it, and treat any `ERROR` line as fatal. The consult's own success value MUST NOT be trusted. [D6]
- P5.4 A consult that emitted `ERROR` MUST discard the engine, because clauses from the failed load stay resident. The caller MUST NOT receive a usable session from that engine. [D6]

### P6 boundary and scope
- P6.1 Budget, cancel and every terminal payload MUST survive `structuredClone`, declared once in `protocol.ts` and imported by both sides. [inherits u2 P2.1, P2.4]
- P6.2 No unbudgeted query surface may be exported for u4 or the UI to reach. [roadmap: "no unbounded query reaches the UI"]
- P6.3 The worker MUST stay the sole owner of `swipl-wasm`; no main-thread module may import it. [inherits u2 P1.1]
- P6.4 No undeclared `swipl-wasm` runtime method may be called from production code. [D8]
- P6.5 `src/engine/terms.ts` decode and encode behavior MUST be unchanged by this unit. [D7]

P6.2-P6.5 scope note (M1 review R35): all four are now decided by `pnpm engine:check`
(`tools/engine-check.mjs`), a gate step between `kb:asset-check` and `copy:check`. P6.2 =
both public entry points require a `budget` parameter and no non-`prolog` `.query`/`.ask`
call site passes fewer than two arguments. P6.3 = exactly one `src/**` module matches any
`swipl-wasm` import form, and it is `src/engine/worker.ts`; the pattern admits a bare
side-effect import, which a `from`-anchored one missed. P6.4 = this project's own
`PrologQuery` and `PrologConstructors` interfaces minus the members the INSTALLED
`common.d.ts` declares must equal the R26 allowlist exactly, so both a new undeclared call
and a package-side declaration change fail it. P6.5's literal "unchanged by this unit" form
expires with the unit; its durable equivalent is the P3 trap battery plus an export-surface
pin on `terms.ts`, since a new export is how a decode path would escape that battery.
Five negative controls, one per clause, each rc 1 naming its own predicate.

### P7 gate
- P7.1 `rm -rf kb/generated && pnpm gate` MUST be rc 0 from committed state.
- P7.2 Every limit, cancel and consult predicate MUST have a committed test that exercises it against the real generated `kb.pvm`, not a stub.
- P7.3 Live tests MUST fail, not skip, when `kb/generated/` is absent. [inherits u2 P5.5]
- P7.4 Client lifecycle tests MUST drive worker error, messageerror, timeout, cancel races, respawn and dispose through an injected worker factory and clock.

## I — invariant surfaces (spot-check even on a green run)

- 337 and schema 1 stay values read from the engine and the manifest, never literal pass conditions.
- No test asserts a constant it computed from the artifact under test.
- A budget-limit test proves the limit fired, not merely that the call returned — an assertion satisfied by a stubbed engine is a defect.
- The stack flag's restored value is read back from the engine after the trip, not assumed.
- Hard-cancel recovery is proven by an overlay that was observably present beforehand.

## G — gate identity

Decisive commands MAIN reruns before the unit closes:
1. `rm -rf kb/generated && pnpm gate` → rc 0.
2. `pnpm test` → every budget, cancel, consult and lifecycle test green against the real PVM.
3. `pnpm engine:check` → P6.2-P6.5 decided mechanically, inside `pnpm gate` since R35.
4. Sibling-path scan → empty.

## Q — probe-corpus seed

Budget cases: each limit at its own trip point in isolation · all four set low at once · a
goal tripping depth and inference simultaneously (`s.compose` measured outer-inference
precedence) · budgets at their maximum · zero / negative / fractional / `NaN` / `Infinity`
/ missing / `2^53` budget values · answer cap 1 against the 7-solution real goal ·
`repeat` under a full budget set.

Cancel cases: cancel before boot · cancel before the first solution · cancel between
solutions · cancel of an already-settled id · cancel of an unknown id · two cancels for one
id · hard cancel with two requests in flight · a request issued during respawn · a stale
response arriving after respawn · dispose during an active query.

Consult cases: clean consult · syntax-error consult · failing-directive consult · a consult
whose `ERROR` arrives on `on_output` rather than `printErr` · the two tolerated
`library(shlib)` qsave warnings, which must not be treated as errors at load.
