# n2 — scope + superseded records, derived under the run context (kernel)

Binds `.agent/spec.md` `Decisions` (superseded statements surface in three places; every answer
states the scope exclusions; one page-wide evaluation date; condition text = the KB's own
controlled-language sentence) and `.agent/contracts/gi-interfaces.md` `Scope + superseded reads`.
Acceptance: `wt/tester-7` A2 (scope) + A3 (superseded, supersessions), merged as they turn green.
Rides n1's run context (`.agent/contracts/n1.md`).

## Mechanism

- Build (clinical helper, `tools/kb/clinical.mjs`, emitted after its existing facts so no
  document line and no `clinical_gate/4` line list moves):
  - `clinical_record_text(Doc, S, "ACE")` for every sentence carrying an exclusion or a
    supersession record (the `% S<n>:` text, verbatim).
  - `clinical_exclusion_site(Doc, S, Line)` for every `guideline_exclusion/1` clause site.
  - `clinical_family(Rec, Doc)` for every recommendation document and every document whose
    coverage section sits under that recommendation's `Implementation considerations`
    (`Rec N > Implementation considerations`), read from the bag's coverage sections.
  - For every sentence a `guideline_supersession/4` record names (generic: the set comes from the
    bag's records, never a document list): `clinical_record_gate(Doc, S, [Lines]) :-
    clinical_use(L, (Head)), …` over ALL its content sites, and its `clinical_record_premise/4`
    facts from its antecedent — a table apart from the answer path's `clinical_premise/4`, whose
    703 premises over 58 sentences the answer graders pin — read without the scope guard AND
    without the supersession guard
    (`guideline_evaluation_date(V), guideline_satisfies(exactly,V,less,N)`), which stay in the
    stored clauses and run when the gate resolves them.
- Proof source (`tools/kb/proof.mjs`, appended): `clinical_scope/1` (exclusion clause bodies via
  `clause/3`, grouped by variant `=@=`, sources sorted, conditions sorted by first source);
  `clinical_supersessions/1` (every record, sorted); `clinical_superseded/2` (question → its
  source documents → their families → records, each statement with `derived` = its record gate
  derives under its premises at `clinical_depth` under the request's run context).
- Service (`src/questions/records.ts` goal texts + decoders, `AnswerService.scope` /
  `.superseded` / `.supersessions`, shapes per `gi-interfaces.md`); `DemoEngine` gains the three
  reads; `createDemoEngine` wires them. A condition's `id` = its first source's sentence key;
  `text` = that sentence's ACE text (equal to g2's `boundaries.conditions`). Dates render
  `YYYY-MM-DD`.

## Predicates (suites `tests/records*.test.ts` + merged `tests/acceptance-gi-records.test.ts`)

- R1 scope: 12 records → 8 conditions, grouped by clause body up to variable renaming (never by
  text); every record in exactly one condition; sources sorted; ids distinct; equal under every
  run context; equal to the network asset's `boundaries.conditions` (A7.4, with g2).
- R2 supersessions: every bag record (3), date-independent, equal to an independent bag reading.
- R3 superseded: the `opioid-use-disorder-treatment` family returns rec12-imp08 S1–S3 with law,
  URL, date and text; every other catalog question returns none; under the sentences' own
  premises `derived` = run date strictly before the record's date, at none / day before / on /
  after — the date guard is one guard beside the scope guard, never its replacement.
- R4 genuine derivation: `derived` comes from the gate under premises — withholding the premises
  turns `derived` false under a date before the boundary, and so does a satisfied scope exclusion
  added to them (a patient with a `sickle-cell-disease-pain`); erasing any one cited clause site
  turns the helper `clinical_record_derived/2` and the public statement's flag false before the
  boundary, the supersession record kept — so the shown flag rests on the KB's clause sites, never
  on the date alone.
- R5 no premise stands in for the date: a premise list holding `guideline_evaluation_date(D)`
  derives nothing without the run context (the date arm precedes the assumption arm).
- R6 budget: every read settles inside the answer budget at none / before / on / after for every
  catalog question; the whole answer → marks → records → proof flow and a recorded chat goal
  timed at each date, figures recorded below.
- R7 refusal: an invalid context is refused `context`, never read as no records.

Each predicate is seen red on the pre-change tree or a planted wrong implementation (commit body).
