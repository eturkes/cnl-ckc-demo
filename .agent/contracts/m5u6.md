# u6 — legacy export lane · kernel

Partly closes C4u3. Depends u3.
Split seam: the `EXPORTED` preflight ↔ the four-export byte oracle.

## What ships today (measured)

**`tools/kb/catalog.mjs` is 22 lines and reads nothing out of the bag's `queries/` tree.** It
re-exports `clinicalArtifacts`, whose 7 records are the curated clinical questions, and emits
`{catalogVersion: 3, entries}`. There is no `EXPORTED` list anywhere in `src`, `tools`,
`tests` or `package.json` — `rg` returns rc 1.

`.claude/rules/kb-build.md` `## Question catalog` still describes the retired design: a
catalog parsed from `queries/pl/*.pl`, an `EXPORTED` declaration that refuses a divergent bag,
six catalog goals with live solution counts. **That section is stale and u6 corrects it.**

What the bag still carries, and what nothing currently reads:

- `queries/*.ace` — 4 exported questions.
- `queries/pl/*.pl` — their compiled goals, grammar
  `'$guideline_query_projection'(goal(G),answers(As))`, `G` in canonical prefix `','/2` form.
- `queries/answers/*.pl` — the expected solutions, committed regression oracles.
- `queries/traces/*.pl` — committed trace oracles, already known to carry no proof-dependency
  edges.

`payloadSource`'s `PAYLOAD` regex admits `data/guidelines/*/pl/*.pl` alone, so `queries/` is
**not** in the PVM. The lane therefore reads the goal text out of the verified bag at run time
and runs `G` against the shipped image; nothing new is compiled in.

`tests/kb-reach.test.ts` keeps `queries/answers/*.pl` out of production reach and deliberately
leaves `tests/` free to read them — that exemption is what makes them oracles.

## The change

A diagnostic lane, separate from the production catalog, that proves the compiled KB still
answers the upstream export exactly.

1. **`EXPORTED` preflight.** The four exported query ids are DECLARED. A bag whose exported
   set differs is refused. Goal text stays derived from the bag; only which questions exist is
   declared, because an extra or renamed query file otherwise enlarges the lane with every
   check agreeing with itself.
2. **Four-export byte oracle.** For each exported id: run its goal on the shipped image, sort
   by SWI standard order over decoded terms (never a byte sort of rendered text), and compare
   against `queries/answers/<id>.pl` byte for byte.
3. **Gate wiring.** Deleting or skipping the lane fails `pnpm gate`.

## Acceptance predicates

| id | predicate | how it is decided |
| --- | --- | --- |
| D1 | The lane names exactly 4 exported ids and they equal the bag's `queries/pl/*.pl` set | preflight, live |
| D2 | A bag with a renamed or extra exported query is REFUSED with that id named | mutant over the in-memory file map |
| D3 | Every exported goal's live solutions byte-match `queries/answers/<id>.pl` | live run, 4/4 |
| D4 | The lane is GREEN on the shipped image at base | gate step |
| D5 | The lane goes RED when a payload dependency of an exported goal is removed | erasure control |
| D6 | Deleting the lane, or skipping it, fails `pnpm gate` | gate-mutant control |
| D7 | The lane compiles nothing new into the PVM: the image bytes are unchanged | `kb:build` output compare |
| D8 | `.claude/rules/kb-build.md` `## Question catalog` describes the shipped design | consistency pass |
| D9 | `pnpm gate` rc 0 | gate |

## Why RED-under-dependency-removal is the whole credit

Ruled in `.agent/spec.md`: the lane is GREEN at base and guards the COMPILED KB, which the
answer-path defect never broke. Its value is D5 — it reddens when the payload stops supporting
the upstream export — not D4.
