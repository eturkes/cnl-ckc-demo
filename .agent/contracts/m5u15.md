# u15 — claim→command registry

Tier: `kernel`. This is the unit that makes every other unit's honesty checkable. It closes
C7 (`.agent/archive/review-expedited.md:102`), whose finding is that claim scope exceeds
evidence scope in shipped copy — and the fix for that is not better wording, it is a committed
command per claim.

Dispatch: to be named at dispatch time; MAIN rules.

## What ships

**`docs/claims.md`** — a committed registry, one row per surviving claim:

| claim | where it is asserted | command that re-derives it | disposition |
|---|---|---|---|

MAIN ruling on the location: `docs/`, not `.agent/`. The registry is the artifact a reader
uses to check the demo's word against the demo, so it belongs with the shipped repository
rather than in the agents' own state. `README.md` links it.

u14 hands u15 its per-claim commands (`.agent/contracts/m5u14.md` A3). u15 turns that list
into the registry, finds the claims u14's surfaces did not hold, and records the dispositions
C7 named.

## Predicates

- **R1 every surviving claim has a row.** The claim set is the union of u14's adjudicated
  `true` and rewritten strings, plus every durable claim outside those surfaces:
  `.claude/rules/*`, `.agent/spec.md` `Artifacts`, the contracts' acceptance rows. A claim
  without a row fails R1, and the sweep that proves the union is complete ships with its
  command and rc.
- **R2 every row names a command that runs FROM COMMITTED STATE.** A scratch-local validator,
  a branch-only suite or a command naming an uncommitted path does not satisfy R2 — those get
  a `deferred` disposition citing their `.agent/deferred.md` row, which is an honest answer,
  not a pass.
- **R3 the commands actually run.** Every command in the registry is executed once and its rc
  recorded. A command that cannot run is a `false` row, not a typo to fix silently.
- **R4 browser and visual claims cite their own rerunnable checks.** `pnpm smoke`,
  `pnpm browser:check` and `pnpm graph:check` are out of `pnpm gate`; a claim resting on one of
  them names it explicitly, so a gate-green report never reads as covering it.
- **R5 the C2 dispositions are recorded.** Five restored evidence classes and the accepted-open
  boundaries, recorded without broad remediation
  (`.agent/archive/review-expedited.md`, `.agent/contracts/m5u7.md`).
- **R6 the registry is honest about what it cannot cover.** A claim no command re-derives is
  recorded as such with the reason. An empty `deferred` column is a claim that the registry is
  complete, and that claim needs its own evidence.

## Why a registry rather than a check

A gate step that graded every claim would have to decide natural-language truth, which no tool
in this stack can do. What a tool CAN decide is whether the cited command exists and exits 0 —
so the registry is the human-judgment layer and R3 is its mechanical half. If u15 finds a
cheap way to run R3 in the gate, that is a win; if it does not, R3 stays a recorded run with
its rc, and the registry says so rather than implying more.

## Red witness

Base = u14's closing commit. The red is the absence: `docs/claims.md` does not exist, and the
sweep R1 names returns claims with no command. Record the sweep's hit count at base — that
number is what the registry has to account for.

## Out of scope

Broad remediation of the accepted-open review rows. They are user-ruled into MAINTAIN
(`.agent/deferred.md` `Accepted-open`); u15 RECORDS their boundaries and does not fix them.
