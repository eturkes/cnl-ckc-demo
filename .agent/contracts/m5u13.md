## What ships

`src/graph/` grows the renderer-neutral view model `m5u8.md:89-99` declares, and BOTH renderers
consume it:

```ts
interface EdgeView {
  id: string;
  source: string;
  target: string;
  relation: string;        // the relation label alone
  scope: readonly string[];// NEAR end, ordered, exactly as the producer recorded it
  farScope: readonly string[] | null; // FAR end; null when the two ends agree
  state: 'context' | 'highlight';
  dashed: boolean;
  label: string | null;    // null = not shown; when shown, relation + near scope + far scope
}
```

**`farScope` is the u13 amendment, ruled by the user.** See V6. The label forms are pinned
here so the producer and the grader agree byte for byte, and so a substring case has something
exact to fail against:

| near `scope` | `farScope` | shown `label` |
|---|---|---|
| non-empty | `null` | `<relation> · <near joined>` |
| empty | `null` | `<relation>` |
| non-empty | non-null | `<relation> · <near joined> → <far joined>` |
| empty | non-null | `<relation> → <far joined>` |

The fourth form renders 644 of the 751 shortcut occurrences, so it is the common case and its
legibility is measured at the 296×384 CANVAS box, never the 320×720 device size. **Operator
display terms do not change here** — `-` keeps whatever the i18n catalog renders, which u12
ships as `negated`. Terminology is fixed; changing a term is u14's unit.

No `EdgeView` type exists in the tree yet. u13 creates it and maps u12's
`SemanticGraphEdge.scopeOperators` → `scope`; the two names differ because `edge.scope` is
already the asset's numeric index into the `scopes` table.

**One view model, two renderers.** `src/graph/canvas.ts` (Cytoscape) and the HTML relation view
in `src/graph/SemanticGraph.svelte` must both read the SAME `EdgeView`, so a scope shown on one
surface cannot be missing from the other. A second derivation per renderer is the drift this
predicate exists to forbid.

## Predicates

- **V1 one seam.** `EdgeView` exists with exactly the declared shape, is produced once, and is
  what both renderers read. `model.ts` keeps ZERO imports and the adapter signature stays
  `mountGraphCanvas(container, onSelect) → {update, recenter, destroy}` (R6).
- **V2 the canvas shows scope.** A shown edge label is exactly `relation` + ordered `scope` —
  never a substring, never reordered (R2) — and `dashed` is per-edge, carrying scope polarity
  alone (R4). Negation must be legible without reading the label text.
- **V3 the fallback shows scope.** The HTML relation view carries the same relation + ordered
  scope for the same edge, including the reversed reading at a target node that S18+ names: a
  reversal may rewrite the relation, never drop or reorder the scope.
- **V4 the conjunction is graded WHOLE against the shipped renderer.** `pnpm graph:check` runs
  R1–R7 over its 14 fixtures × 2 viewports AND C1–C12 over 2 devices × 2 views + both
  fallbacks, on the SHIPPED `mountGraphCanvas` and the SHIPPED `SemanticGraph.svelte`, and the
  new scope readings join it. **A model-side or jsdom assertion does not satisfy V4** — both
  are blind to rendered text by construction.
- **V5 `graph:check` terminates on its own.** The campaign completes both readings and both
  summaries, then hangs; `test-owners` killed it at 600 s (rc 143). **MAIN ruling: this closes
  in u13, not as a deferred row.** A grader that must be killed by wall clock cannot
  distinguish a finished campaign from a hung browser, so V4's green would be unreadable — the
  fix is on the shortest path to u13's own artifact, not an off-path improvement. Accept:
  `pnpm graph:check` exits with rc 0 inside its own budget, and a planted non-terminating page
  still fails it BY NAME rather than by wall clock.
- **V6 a spanning edge shows BOTH endpoint scopes. USER-RULED.** Measured independently by
  `prod-view` and `orc-view`, agreeing: **736 of 751 synthesized `condition supports`
  occurrences — 333 of 344 projected shortcut groups, across 12 scope-pair shapes — join
  endpoints whose scopes DIFFER.** The four commonest shapes are `[] → [should]` 527,
  `[] → [may]` 117, `[-] → [-, should]` 19, `[-] → [should]` 17. Spanning is the NORMAL case for
  a shortcut edge, so `edge:512:12` was never the exception it looked like, and a per-edge
  remedy would leave 332 groups broken.

  One scope per edge cannot carry that without either dropping a real operator or composing a
  chain no `scopes` record holds. Both are forbidden: the drop is the silent loss u12's P6
  refuses, and the composition would let an edge read as a claim the source denies, which is the
  user's binding polarity ruling. `[should]` at the source against `[-, may]` at the target
  composes to `[should, -, may]`, which exists nowhere in the asset. **The ruling is therefore
  `farScope`, not composition**, and `scope` stays byte-for-byte what the producer recorded.

  The 38 divergent cases — where neither end's scope is a prefix of the other — are a
  PRODUCER question at `tools/kb/graph.mjs:398`, the S12+ synthesis site. User-ruled QUEUED to
  `.agent/deferred.md`, not investigated in u13, and the shipped edge population does not move.
- **V7 no silent loss, at the renderer this time.** Whatever a view cannot show is disclosed or
  refused where it is dropped. u12's P6 bound the model; V7 binds the surfaces.

  **MAIN ruling — a cap needs TWO disclosures, separately countable.** A cap that removes a
  whole relation identity is a SIZE truncation and a count discloses it. A cap that SPLITS a
  relation identity — keeping some scope variants and cutting others — is a MEANING change and
  a count does not disclose it: the reader sees `condition supports · negated` present,
  `condition supports · should` absent, and concludes the second does not exist. That is a claim
  the source denies, reached through a size cap instead of a dropped field. So every cap reports
  (1) rows removed and (2) **shown relations missing at least one of their scope variants**.

  `orc-view`'s asset-side census of the shipped caps, branch `ac028ec`, is V7's red witness:

  | cap | rows dropped | relation identities SPLIT |
  |---|---|---|
  | `search24`, query `e` | 1,276 of 1,300 concept nodes, silently | — |
  | `answer24` | 92 nodes / 273 edge-view rows over 12 fixtures | 15 scoped variants |
  | `fallback60` | 933 edge rows over 10 roots | **50 variants across 31 identities** |
  | `neighborhood80` | 500 nodes / 2,032 view-edge rows over 6 roots | **0** |
  | `edge480` | binds nowhere at defaults | — |
  | canvas, node index | 0 | 0 |

  `neighborhood80` is the shape to aim for: it drops a great deal and still means what it says.
  `fallback60` is the first fix. `search24` showing 24 of 1,300 in silence is its own row,
  independent of scope. Disclosure copy lands where the existing hidden-total disclosure already
  lives, so u14 adjudicates one surface; both locales move together or `copy:check` reddens on
  key parity.
- **V8 the accepted surfaces are untouched.** The graph's LOOK is open to change by user
  ruling; answer panel, ladder, combobox, theme, type and copy layout are not. A change forcing
  a visual difference there stops and asks.

## Firing inputs

Every new reading ships the input that makes it fail, into `.claude/rules/gate.md`
`Firing inputs`. The existing `graph:check` rows already carry `dashControl` (a 0 → 1 → 0
reading off the live renderer), `SEPARATION_PX` at 0, the detached selection callback, a
refused `graphUrl` and a `--graph-*` palette set to `initial`. V2 and V3 each need one more:
a scope element dropped from a rendered label must be REFUSED by name, and the emptied reading
table must fail rather than report `0 readings`.

`graph:check`'s summary counts are already required non-zero, so a campaign that graded nothing
fails instead of reporting green. Keep that property when the scope readings join.
