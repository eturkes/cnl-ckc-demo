## What ships

`src/graph/` grows the renderer-neutral view model `m5u8.md:89-99` declares, and BOTH renderers
consume it:

```ts
interface EdgeView {
  id: string;
  source: string;
  target: string;
  relation: string;        // the relation label alone
  scope: readonly string[];// SOURCE end, ordered, exactly as the producer recorded it
  farScope: readonly string[] | null; // TARGET end, ordered; null IFF that end is unscoped
  state: 'context' | 'highlight';
  dashed: boolean;
  label: string | null;    // null = not shown; when shown, the canonical source→target reading
}
```

**`farScope` is the u13 amendment, ruled by the user.** See V6.

**Data is DIRECTION-FIXED; presentation is READER-RELATIVE (user ruling).** The two fields name
endpoints, never reading order: `scope` is always the source end and `farScope` always the
target end, byte-for-byte. `farScope` is `null` **if and only if the target end is genuinely
unscoped**. An earlier MAIN statement nulled it when the two ends AGREE; that is withdrawn and
must not be restored. Under a flipping reading it destroys information — when both ends carry
`should`, a reader standing at the target has no way to recover their own near scope, and the
label silently loses the modality it exists to show.

One composer serves both surfaces. Given the node the reader is at:

- at the SOURCE — and on the CANVAS, which is always the canonical reading:
  `near = scope`, `far = farScope ?? []`
- at the TARGET: `near = farScope ?? []`, `far = scope`, relation rewritten through
  `REVERSED_RELATIONS`
- then `far` is OMITTED if it is empty **or** deep-equals `near`

The four forms are pinned against the RESOLVED `(near, far)` — not against `(scope, farScope)`
literally — so the producer and the grader agree byte for byte and a substring case has
something exact to fail against:

| resolved `near` | resolved `far` | shown `label` |
|---|---|---|
| non-empty | omitted | `<relation> · <near joined>` |
| empty | omitted | `<relation>` |
| non-empty | shown | `<relation> · <near joined> → <far joined>` |
| empty | shown | `<relation> → <far joined>` |

`→` therefore carries ONE meaning everywhere: the other end, away from the reader.

**No trimming, no composition.** Where the far end nests the near one — `[-]` against
`[-, should]` — both sides write out in full: `condition supports · negated → negated · should`.
Eliding the repeated `negated` would render a nested pair identically to a divergent one, and
the 38 divergent cases are exactly where that would lie. Verbosity barely bites: 527 of the 751
occurrences are `[] → [should]`, where the near side is empty and nothing repeats.

Worked, and re-derivable from the asset:

| edge | `scope` | `farScope` | at source | at target |
|---|---|---|---|---|
| `edge:4501:11` | `[]` | `['should']` | `condition supports → should` | `supported by condition · should` |
| `edge:512:12` | `['-']` | `['-','should']` | `condition supports · negated → negated · should` | `supported by condition · negated · should → negated` |
| ends agreeing | `['should']` | `['should']` | `<relation> · should` | `<relation> · should` |

`edge:4501:11` carries NO `scope` key in the asset — the source end is genuinely unscoped, not
scope-zero. Its target scope resolves through the same-line declaration `edge:4501:0` →
`scopes[336]` → `operator: "should"`. A `scopes` record is
`{id, chain, operator, document, sentence, reference}` with `operator` a SINGLE string, so an
endpoint's operator set comes from walking its `chain`, never from one record's field.

The fourth form renders 644 of the 751 shortcut occurrences, so it is the common case and its
legibility is measured at the 296×384 CANVAS box, never the 320×720 device size. **Operator
display terms do not change here** — `-` keeps whatever the i18n catalog renders, which u12
ships as `negated` (`src/graph/model.ts:437`, which passes every other operator through
unchanged). Terminology is fixed; changing a term is u14's unit.

## Predicates

- **V1 one seam.** `EdgeView` exists with exactly the declared shape, is produced once, and is
  what both renderers read. `model.ts` keeps ZERO imports and the adapter signature stays
  `mountGraphCanvas(container, onSelect) → {update, recenter, destroy}` (R6).
- **V2 the canvas shows scope.** A shown edge label is exactly `relation` + ordered `scope` —
  never a substring, never reordered (R2) — and `dashed` is per-edge, carrying scope polarity
  alone (R4). Negation must be legible without reading the label text.
- **V3 the fallback shows scope.** The HTML relation view carries the same relation + ordered
  scope for the same edge, including the reversed reading at a target node that S18+ names: a
  reversal may rewrite the relation, never drop or reorder the scope.
- **V4 the conjunction is graded WHOLE against the shipped renderer.** `pnpm graph:check` runs
  R1–R7 over its 14 fixtures × 2 viewports AND C1–C12 over 2 devices × 2 views + both
  fallbacks, on the SHIPPED `mountGraphCanvas` and the SHIPPED `SemanticGraph.svelte`, and the
  new scope readings join it. **A model-side or jsdom assertion does not satisfy V4** — both
  are blind to rendered text by construction.
- **V5 `graph:check` terminates on its own.** The campaign completes both readings and both
  summaries, then hangs; `test-owners` killed it at 600 s (rc 143). **MAIN ruling: this closes
  in u13, not as a deferred row.** A grader that must be killed by wall clock cannot
  distinguish a finished campaign from a hung browser, so V4's green would be unreadable — the
  fix is on the shortest path to u13's own artifact, not an off-path improvement. Accept:
  `pnpm graph:check` exits with rc 0 inside its own budget, and a planted non-terminating page
  still fails it BY NAME rather than by wall clock.
- **V6 a spanning edge shows BOTH endpoint scopes. USER-RULED.** Measured independently by
  `prod-view` and `orc-view`, agreeing: **736 of 751 synthesized `condition supports`
  occurrences — 333 of 344 projected shortcut groups, across 12 scope-pair shapes — join
  endpoints whose scopes DIFFER.** The four commonest shapes are `[] → [should]` 527,
  `[] → [may]` 117, `[-] → [-, should]` 19, `[-] → [should]` 17. Spanning is the NORMAL case for
  a shortcut edge, so `edge:512:12` was never the exception it looked like, and a per-edge
  remedy would leave 332 groups broken.

  One scope per edge cannot carry that without either dropping a real operator or composing a
  chain no `scopes` record holds. Both are forbidden: the drop is the silent loss u12's P6
  refuses, and the composition would let an edge read as a claim the source denies, which is the
  user's binding polarity ruling. `[should]` at the source against `[-, may]` at the target
  composes to `[should, -, may]`, which exists nowhere in the asset. **The ruling is therefore
  `farScope`, not composition**, and `scope` stays byte-for-byte what the producer recorded.

  The 38 divergent cases — where neither end's scope is a prefix of the other — are a
  PRODUCER question at `tools/kb/graph.mjs:398`, the S12+ synthesis site. User-ruled QUEUED to
  `.agent/deferred.md`, not investigated in u13, and the shipped edge population does not move.
- **V7 no silent loss, at the renderer this time.** Whatever a view cannot show is disclosed or
  refused where it is dropped. u12's P6 bound the model; V7 binds the surfaces.

  **MAIN ruling — a cap needs TWO disclosures, separately countable.** A cap that removes a
  whole relation identity is a SIZE truncation and a count discloses it. A cap that SPLITS a
  relation identity — keeping some scope variants and cutting others — is a MEANING change and
  a count does not disclose it: the reader sees `condition supports · negated` present,
  `condition supports · should` absent, and concludes the second does not exist. That is a claim
  the source denies, reached through a size cap instead of a dropped field. So every cap reports
  (1) rows removed and (2) **shown relations missing at least one of their scope variants**.

  `orc-view`'s asset-side census of the shipped caps, branch `ac028ec`, is V7's red witness:

  | cap | rows dropped | relation identities SPLIT |
  |---|---|---|
  | `search24`, query `e` | 1,276 of 1,300 concept nodes, silently | — |
  | `answer24` | 92 nodes / 273 edge-view rows over 12 fixtures | 15 scoped variants |
  | `fallback60` | 933 edge rows over 10 roots | **50 variants across 31 identities** |
  | `neighborhood80` | 500 nodes / 2,032 view-edge rows over 6 roots | **0** |
  | `edge480` | binds nowhere at defaults | — |
  | canvas, node index | 0 | 0 |

  `neighborhood80` is the shape to aim for: it drops a great deal and still means what it says.
  `fallback60` is the first fix. `search24` showing 24 of 1,300 in silence is its own row,
  independent of scope. Disclosure copy lands where the existing hidden-total disclosure already
  lives, so u14 adjudicates one surface; both locales move together or `copy:check` reddens on
  key parity.
- **V8 the accepted surfaces are untouched.** The graph's LOOK is open to change by user
  ruling; answer panel, ladder, combobox, theme, type and copy layout are not. A change forcing
  a visual difference there stops and asks.

## O6 adjudication — `orc-view`'s objections to these predicates

`orc-view` graded the predicates themselves against the corpus (report row O6, branch
`wt/orc-view` `799cef9`). Five hit; all five are upheld.

- **V2 admitted `label: null`.** `{relation:'condition supports', scope:['should'], label:null}`
  satisfied "every shown label is exact" while the modality stayed invisible, because a null
  label is vacuously exact. Ruled: for a scope-BEARING edge, `label` may be null only where the
  renderer discloses the suppression; an edge that carries a scope and shows nothing is a V7
  silent loss, not a V2 pass. The emptied-reading control only prevents a zero-row campaign and
  never reached this.
- **V3 could certify a partial reading.** A model-derived expected value reproduces the
  model's own defect: `edge:512:12` renders `supported by condition · negated`, exactly matching
  its model scope `['-']`, while the target end is `['-','should']`. Ruled: V3's expected value
  is ASSET-derived, from both endpoint declarations. `orc-view`'s oracle is that derivation.
- **V4 covers 66 of 333 affected spanning groups.** The 12 answer fixtures plus `worst-bounded`
  reach 66; 267 can regress unread. First uncovered: `edge:75:18`, `edge:163:14`, `edge:192:25`,
  `edge:192:26`, `edge:192:27`. Ruled: V4 declares its measured coverage as a number in the
  campaign summary. Widening the fixture set is STRENGTHENING, not loosening, so it needs no
  separate approval — but it is not free, and the honest minimum is that the summary states
  what fraction of affected groups it read.
- **V6 named no all-asset inventory.** A check covering `edge:512:12` alone satisfied the named
  witness while 332 other affected groups survived. Ruled: V6 grades the whole projected
  population, not the witness edge.
- **V7's graders omitted the measured loss.** This is the sharpest one and it is confirmed
  independently: `test-view` measured V7 base-GREEN while `orc-view` measured `search24` on
  query `e` silently dropping 1,276 of 1,300 concept nodes and `fallback60` splitting 50 scope
  variants across 31 relation identities. A check that passes on a surface that loses that much
  is not grading the ruling. Ruled: **naming incompleteness is not enough — a cap must report
  the SPLIT COUNT, separately from the row count.** Generic truncation copy satisfies the row
  count and says nothing about meaning. `neighborhood80` is the shape to aim for: 2,032 rows
  dropped, 0 identities split.
