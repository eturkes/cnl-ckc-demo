# u10 — graph integration · kernel

Depends — u9 (the shipped renderer it grades). Closes the theme half already landed plus the
component half below.

## What was already shipped

The canvas reads every colour from an `src/app.css` token, `graph:check` gained its `palette`
and `theme` rules, and the law is in `.claude/rules/graph.md`. Those are predicates P1-P3
below; C1-C12 are the remaining half.

## The gap this unit closes

`tests/semantic-graph.dom.test.ts` MOCKS `src/graph/canvas.js` and jsdom has no canvas, so
every interaction in `SemanticGraph.svelte` is graded against a stub that records calls. The
stub cannot say whether a selection reached the renderer, whether the path the panel lists is
the path the canvas highlights, whether expanding added nodes to the drawn graph, or whether
recentering moved the viewport. `pnpm graph:check` already mounts the adapter DIRECTLY
(`tools/graph-probe/probe.ts`), which grades the adapter and skips the component.

So the seam between the two — the only place where the component's state and the renderer's
output have to agree — has no grader at all. C1-C12 put one there by mounting the SHIPPED
component, and each interaction is read on BOTH sides of that seam.

## Viewport

**The component probe sizes the viewport to the DEVICE, not to the canvas box.**
`tools/graph-probe/probe.ts` does the opposite on purpose: it mounts the adapter into a stage
that fills the viewport, so the viewport has to be the `.graph-shell .canvas` box for the fit
zoom to be the product's. Here the component computes its own box — `.canvas` is `width: 100%`
by `clamp(24rem, 62vh, 40rem)` inside a page-width shell — so the device size is the input and
the box is an output. 1280x900 and 320x720 are the two devices, the same pair whose measured
boxes the adapter probe uses.

## Firing inputs

`graph:check` already ships `dashControl` (R4) and the `theme`/`palette` rules' own controls.
The component half adds two, both of which break a REAL input rather than a fixture:

| predicate | broken input | how it runs |
| --- | --- | --- |
| C9 | `graphUrl` pointed at a path the dev server does not serve | the load path must reach `[role=alert]`; a silent `ready` fails |
| C10 | every `--graph-*` token set to `initial` on the mount host | `mountGraphCanvas` must throw and the component must keep the HTML view |

Those two are the product's OWN failure paths, so they are the positive controls for the rest
of the sweep at the same time: C9 proves the probe can tell a failed load from a loaded one,
and C10 proves it can tell a mounted renderer from an absent one. `componentControl` in
`tools/graph-check.mjs` additionally re-runs the interaction sweep against a harness whose
selection callback is detached, and requires C2's emit predicate to refuse it.
