# n1 — evaluation date as run context (kernel)

Binds `.agent/spec.md` `Decisions` (one page-wide evaluation date; MAIN: the evaluation date is
run context) and `.agent/contracts/gi-interfaces.md` Engine. Reference mechanism: spike
`wt/builder-40` `cf3fd3e` (`.agent/contracts/gi-orientation.md` K1–K6), re-implemented here under
the full gate. Acceptance: `wt/tester-7` A1 (merged as it turns green).

## Mechanism

- Prolog, appended to `PROOF_SOURCE` (`tools/kb/proof.mjs`) so no content-site or gate line
  moves: `clinical_run(Ctx, Goal)` — `setup_call_cleanup` saves the prior run context, sets
  `'$clinical_run_context'` to `Ctx` (`none` | `date(YYYYMMDD)`), calls `Goal`, restores the prior
  value on every exit (`nb_delete` when there was none); one static clause
  `guideline_evaluation_date(D) :- nb_current('$clinical_run_context', date(D))`; a `derive/5`
  arm before the comparison arm answering `guideline_evaluation_date(D)` from the run context with
  a line-free `context(evaluation_date(D))` leaf.
- Engine: `RunContext = { readonly evaluationDate: string | null }`, a REQUIRED argument of
  `EngineClient.query` + `.prove` and of the worker protocol; validated (`YYYY-MM-DD`, a real
  Gregorian day, year 0001–9999) and frozen on admission, else `{ code: 'context' }` before any
  Prolog; every goal runs as `clinical_run(none|date(N), Goal)` inside the existing budget
  wrapper; a fresh engine sets the context to `none` before it is published; a request arriving
  while another is open is refused `{ code: 'busy' }` before parsing (closes the queue row `The
  engine session interleaves concurrent requests`); the proof cache keys on goal + context; a
  dated proof's steps open with one `{ kind: 'context', goal: 'evaluation_date(N)' }` record, every
  dependency leaf checked equal to it.
- Service + controller: `AnswerService.ask` / `.marks` and `DemoEngine` take the context; the
  demo controller captures the page date ONCE per run at admission — the answer, its marks and
  its trace proof all run under it — and a settled answer keeps it; a chat turn captures the page
  date when sent, every goal of the turn runs under it, and each query card shows the goal and
  the date as separate fields. Until n3 adds the control, the page date is `null`.

## Predicates (suites: `tests/run-context*.test.ts` + merged `tests/acceptance-gi-context.test.ts`)

- R1 admission: every valid ISO day is admitted and every malformed or impossible one refused
  `context` with zero Prolog calls (property over generated strings + named boundaries).
- R2 freeze: mutating the caller's object after admission leaves the run's date unchanged.
- R3 native ≡ interpreter: for none / 2022-12-01 / 2022-12-29 / 2023-01-01, a native
  `guideline_evaluation_date(D)` and `derive/5` agree, and `rec12-imp08` S1–S3's deontic heads
  derive under their premises only before 2022-12-29.
- R4 restore: after failure, exhaustion, early close, answer cap, error, cancel, inference / depth
  / stack limits and a soft deadline, the raw context read before any wrapper is the prior one; a
  hard-killed worker's replacement starts at `none`.
- R5 busy: a query and a proof arriving while a streamed query is open are refused `busy` with zero
  Prolog calls and no cache operation; the open query finishes under its own date.
- R6 proofs: a dated proof opens with exactly one context record equal to the admitted date; an
  undated proof keeps its pre-change kinds and source lines and is `=@=` its old goal shapes
  (characterization C3 stays green); a date change misses the proof cache, a repeat hits.
- R7 guard: the read-only entry refuses model goals naming `clinical_run` or any global-variable
  builtin; a permitted KB goal still answers.
- R8 one run, one date: changing the page date while a run is live alters neither its answer, its
  marks nor its proof; the settled answer reports its run's date.
- R9 chat: a turn's goals all run under the date captured at send; its cards show it.
- R10 `engine:check` pins the context argument at every `src` call site (user-approved re-pin,
  the old arity pin's red recorded).

Each predicate is seen red on the pre-change tree or a planted wrong implementation (commit body).
