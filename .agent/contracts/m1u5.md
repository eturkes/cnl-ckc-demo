## Source

## Decisions

- **D1 host element = `<div role="combobox" tabindex="0">`.** Not a readonly
  `<input>`, not a `<button>`. APG's select-only reference host; a readonly input
  announces "read only edit" for a widget that accepts no text, raises a mobile
  keyboard, and a button carries its own Space/Enter click semantics. The
  roadmap's "reads as future free-text" requirement is visual, so it lives in CSS
  as a text-field affordance; the later free-text intake swaps the host to
  `<input role="combobox" aria-autocomplete="list">` and keeps everything else.
- **D2 hand-authored, `bits-ui` rejected.** The library works: the spike's 21 dom
  cases pass on it. It is rejected on surface, not on correctness — 7 runtime
  packages including the required peer `@internationalized/date`, a date library
  pulled in for a six-item static list; the popup portals outside the app root,
  and u6 layout, u7 theming and M4's static/CSP decision all need that DOM; its
  module graph costs the dom project 10.06 s against a 13.9 s whole-gate
  baseline. The bundle delta is UNMEASURED — the spike stalled at 2/30 rows — so
  this ruling rests on dependency surface, DOM ownership and gate time alone.
- **D3 keyboard divergences ruled for determinism.** APG's keyboard table and its
  example JS disagree three times; each ruling below is what the suite asserts.
  Closed `Alt+ArrowUp` = no-op (the table specifies `ArrowUp` only, and the
  general pattern scopes `Alt+ArrowUp` to an open popup). Typeahead = 500 ms
  case-insensitive prefix buffer, and a repeated single character cycles matches.
  Open `Alt+ArrowUp` = commit the active option and close.
- **D4 `svelte-check --fail-on-warnings` joins `pnpm check`.** The Svelte compiler
  emits the only a11y diagnostics in this toolchain: `eslint-plugin-svelte`
  3.23.0 ships 86 rules and 0 `a11y-*` rules, so without the flag every a11y
  warning passes the gate at rc 0.
- **D5 DOM tests run in their own vitest project.** `tests/**/*.dom.test.ts` under
  jsdom 29.1.1 with `resolve.conditions: ['browser']`; the node project excludes
  that glob so swipl-wasm keeps resolving its node entry. jsdom 30.0.1 cannot
  start on Node v20.19.2.
- **D6 no `test-m1u5` teammate.** The predicates below were authored diff-blind by
  `map-m1u5` from the specification alone, and MAIN writes the suite red from
  them before implementing. u2, u3 and u4 each dispatched a `test` teammate and
  none was harvested — three open `.agent/polish.md` entries — so at this unit's
  budget position a fourth repeats a measured failure.
- **D7 controlled leaf.** `src/questions/QuestionCombobox.svelte`, props
  `{ selected: QuestionId | null; onSelect: (id: QuestionId) => void }`. It holds
  no selection state, imports no engine module, and renders a prompt while
  `selected` is null.

## Predicates

Structure, asserted on the rendered DOM:

- **S1** the focusable element carries `role="combobox"` and `aria-labelledby`
  pointing at its visible label; its accessible name is the label, not its value.
- **S2** `aria-expanded` is `"false"` while the listbox is hidden, `"true"` while
  it is rendered.
- **S3** `aria-controls` equals the listbox `id` in both states.
- **S4** no `aria-haspopup` attribute: `role="combobox"` implies `listbox`.
- **S5** the popup is `role="listbox"`, named by the same label, and owns exactly
  six `role="option"` children in `QUESTION_IDS` order.
- **S6** with selection `q`, option `q` carries `aria-selected="true"` and the
  other five carry `"false"`.
- **S7** open: `aria-activedescendant` equals the active option's `id`; closed:
  the attribute is absent; `document.activeElement` is the combobox in both.
- **S8** the combobox's own text is the selected question, or the prompt when
  `selected` is null; no descendant is focusable.

Keyboard while closed:

- **K1** `ArrowDown` and `Alt+ArrowDown` open, leave the active option at the
  selection, and emit no `onSelect`.
- **K2** `ArrowUp` opens with option 1 active; `Alt+ArrowUp` does nothing.
- **K3** `Enter` and `Space` open and emit no `onSelect`.
- **K4** `Home` opens with option 1 active, `End` with option 6 active.
- **K5** a printable character opens and activates the first question whose text
  starts with the typed prefix, case-insensitively; the buffer expires after
  500 ms; a repeated single character cycles matches.

Keyboard while open:

- **K6** `ArrowDown` and `ArrowUp` move the active index by one and clamp at
  option 6 and option 1; neither emits `onSelect`.
- **K7** `Home` and `End` activate option 1 and option 6 without emitting.
- **K8** `Enter` emits `onSelect(active)` exactly once, closes, and leaves
  `document.activeElement` on the combobox.
- **K9** `Escape` closes, emits nothing, and resets the active option to the
  controlled selection.
- **K10** `Tab` emits `onSelect(active)` exactly once, closes, and does not call
  `preventDefault`.
- **K11** `Alt+ArrowUp` emits `onSelect(active)` exactly once and closes.

Pointer:

- **P1** a click on the combobox toggles the listbox and emits nothing.
- **P2** a click on option `q` emits `onSelect(q)` exactly once, closes, and
  returns focus to the combobox.
- **P3** `focusout` to a node outside the widget closes it and emits nothing.

Behaviour:

- **B1** every active-option change calls `scrollIntoView({ block: 'nearest' })`
  on that option.
- **B2** every `onSelect` argument is a member of `QUESTION_IDS`; no key sequence
  produces free text or an unknown id.
- **B3** `axe.run` over the widget returns zero violations closed and open;
  `color-contrast` is the only permitted `incomplete` id under jsdom.
- **B4** `pnpm check` reports 0 errors and 0 warnings with `--fail-on-warnings`.

## Invariants

- The component imports from `./catalog.js` only; no `../engine/` import, no
  `AnswerService`, no worker.
- The component owns no selection state: rendering with a fixed `selected` prop
  and pressing `Enter` on another option changes the DOM only after the parent
  passes a new prop.
- `onSelect` fires once per commit, never on cancel paths (`Escape`, outside
  click, closed-state keys).

## Corpus

Six catalog ids in `QUESTION_IDS` order: `category-a-recommendations`,
`category-b-recommendations`, `dosage-reduction-content`,
`evidence-type-1-recommendation`, `evidence-type-3-recommendation`,
`recommendation-exists`. Question text comes from
`kb/generated/question-catalog.json`, so the suite reads labels through
`QUESTION_CATALOG` and never hard-codes a sentence.
