## The change

1. **Perturbation battery** — three arms over `guideline_*`, each binding a different surface.
   Additive: the M1 recipe (four schema predicates declared dynamic, a whole new proof
   supplied) moves the live export-lane statement. Erasure: one cited clause removed drops
   exactly its document from the clinical answer set AND turns its proof to `failure`.
   Relocation: a cited clause moved to a new line leaves the answer byte-identical and moves
   the line-keyed proof.
2. **Required-check execution inventory** — `tools/binding-check.mjs` owns a DECLARED table of
   suite → case ids, runs the whole suite once and requires every declared case to have
   PASSED. It replaces `pnpm test` in the gate chain, so the inventory grades the gate's own
   run and costs no second execution. `kb:export-check` keeps the bag preflight and hands its
   case requirement to the inventory.
3. **Independent browser answer lane** — the rendered canonical answer is compared against
   bytes derived in Node from the vendored bag, never scraped from the app and never read
   from a committed fixture the app also reads.
4. **C2 disposition record** — each of the five retired classes is restored naming its check,
   or carries a specific rationale.

## Why the inventory replaces `pnpm test` rather than adding a step

Grading a separate run costs a second execution of every live suite and grades a run the gate
did not use. Reading a report from a previous run raises a staleness question no check can
settle cheaply. Running the suite THROUGH the inventory settles both: one execution, and the
report graded is the one the gate just produced.
