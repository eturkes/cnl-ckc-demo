# u16 — free-text patient intake

Tier: `kernel` for u16b–u16g (it decides which shipped recommendation answers a user), `data`
for u16a (the whole gate re-checks every consumer), `docs` for u16h. Rulings → `.agent/spec.md`
`Decisions`; plan review → `consultant-1`, 4 pass / 6 fail, every fail folded in below.

A user describes a clinical situation in free text. ONE judgment request (TypeSafe System One,
model `jev-1.13.0`) returns typed probabilities; a deterministic selector turns them into one of
three outcomes; every recommendation shown as an answer is DERIVED in Prolog by the existing
per-sentence predicate `clinical_derive/4`. The judgment layer can only choose among the 48
shipped `clinical_rule/3` rules and among the user's own words, so it cannot fabricate a
recommendation or a gap term.

## Definitions

**Rule id** = `<document>:<sentence>`, e.g. `cdc2022-opioid-rec04:5`.

**Artifact** `intake-vocabulary.json`:

```ts
interface IntakeVocabulary {
  vocabularyVersion: 1;
  digest: string;                 // sha256 hex of the artifact with `digest` removed
  conditions: { id: string; text: string }[];            // 24, ids c01.. by first appearance
  sections: { id: string; heading: string; documents: string[] }[];   // 4, ids s1..s4
  vocabulary: string[];           // distinct condition texts + action objects + modifier values
  rules: {
    id: string; document: string; sentence: number;
    trigger: { kind: 'condition'; condition: string } | { kind: 'section'; section: string };
    painSet: ('acute' | 'subacute' | 'chronic')[];      // [] = agnostic; that order
    section: string;              // the document's section id
    question: string;             // the built-in catalog question whose sources hold `document`
    goal: string;                 // `clinical_derive(<doc atom>,<sentence>,Rule,Proof)`
  }[];                            // 48, in `clinical_rule/3` emission order
}
```

**painSet** = the pain types `(acute|subacute|chronic)-pain` named in the rule's own condition +
action text, matched hyphen-bounded (`subacute-pain` never yields `acute`); if none, the union
over the rule's document; if still none, `[]`.

**Sections** = the four heading lines of the bag's `source/box3-extraction.txt` of the form
`<heading> (Recommendations <list>)`, `<list>` = decimal numbers joined by `, `, ` and ` or
`, and `; heading copied byte-for-byte; `<n>` → document `cdc2022-opioid-rec<nn>`.

**Chunker** (frozen; the consultant's P3/P9 made it a graded contract):

1. Hard boundaries: `, ; : ( ) [ ] { } " ! ?`, any line break, and `.` unless the characters on
   both sides are ASCII digits (`2.5 mg` stays one token).
2. Tokens = maximal non-whitespace runs inside a boundary segment.
3. A token is a stopword iff its lowercase form, stripped of leading/trailing `'’`, is in
   `STOPWORDS` below. Negators (`no`, `not`, `never`, `without`, `denies`, `denied`) are NOT
   stopwords, so negation stays inside its chunk.
4. Chunk = maximal run of consecutive non-stopword tokens in one segment; `text =
   description.slice(start, end)` from the first token's start to the last token's end.
5. A chunk with no `\p{L}` or `\p{N}` is discarded. A chunk longer than 80 UTF-16 units is cut
   greedily into consecutive token runs of ≤80; a single token over 80 is discarded and counted.
6. Deduplicate on lowercase text, keeping the first. Keep the first 16 by `start`;
   `overflow` = every distinct chunk beyond them + every discarded over-long token.

`STOPWORDS` = `a an the and or but if then than that this these those with for from to of in on
at by as per via about into over under after before during since until while because so is are
was were be been being am has have had having do does did will would should shall could can may
might must i me my we our us you your he him his she her they them their it its who whom whose
which what when where why how also now just only very some any more most less much many patient
patients take takes taking took taken start starts started starting want wants wanted ask asks
asked asking consider considers considered considering think thinking need needs needed receive
receives received receiving`. (`use`/`uses`/`used`/`using` were struck before any code bound
them: they split "opioid use disorder".)

**Request** = `{ model: 'jev-1.13.0', state: { description }, questions }` with question ids, in
order: `c01`…`c24` (Noul, one per condition), `pain` (Choice over `acute subacute chronic
unstated other`; `hatch: false` omits `other`), `s1`…`s4` (Noul, one per section heading),
`t01`…`tNN` (Noul, one per candidate, N = candidate count). Nothing else enters `state`.

**Noul yes** = value ≥ 0.5.

**Selection**: `refused` iff `pain.choice === 'other'`. Otherwise a rule answers iff its
trigger Noul says yes AND (`painSet` empty OR `pain.choice ∈ painSet`); `unstated` therefore
admits agnostic rules alone. ≥1 answering rule → `answered` (rule ids in artifact order), else
`no-match`. Gap terms = candidates whose Noul says yes, on `answered` and `no-match` only.

### u16c judgment core

- **K1 chunker.** `extractCandidates` implements the Definitions exactly: every candidate text
  is `description.slice(start, end)`; ≤16 candidates; each ≤80 units; order by `start`;
  case-insensitive unique; `overflow` counted; deterministic.
- **Q1 request.** `buildRequest` emits exactly the declared question ids, in order, with the
  pinned model and `state = { description }`; `hatch: false` removes only `other`. Question text
  derives from the vocabulary + candidates alone.
- **J1 parser.** `parseJudgment(raw, request)` validates against the request it is given, never
  a fixed option set (consultant P6): resolved model = the request's; answer ids exactly the
  request's; each answer's `type` matches its question; Noul values finite in [0,1]; Choice
  `probabilities` keys exactly the request's options, each finite in [0,1], summing to 1 ± 1e-6;
  `choice` an option of maximal probability. Each violation throws, naming the question id.
- **S1 selector.** `select` implements Selection exactly, including the 0.5 boundary, the
  `unstated` rule and `refused` overriding every Noul; answered ids come in artifact order; each
  match carries its trigger id + value.
- **S2 gap terms are user text.** For ANY description and ANY judgment `parseJudgment`
  accepts, every gap term is one of `extractCandidates(description)`'s candidates (offsets
  included).
- **C1 clients.** `HttpJudgmentClient` posts `application/x-www-form-urlencoded` `description` +
  `vocabulary` (the digest) to same-origin `/api/judgment` — no `JSON.stringify` in `src/`
  (`kb:asset-check` bans it) — and REBUILDS the request locally to parse the response. `200` +
  valid → judged; `429` → `rate-limited`; `409` → `stale`; any other status, network failure,
  abort-free timeout, non-JSON or parser refusal → `unavailable`; never a no-match.
  `ReplayJudgmentClient` returns the recorded response for an exact description, throws on a
  miss, and honours an abort before and after its async boundary.

### u16d derivation

- **D1 ids only.** `IntakeService` takes rule ids; an id absent from the artifact is refused
  before any engine call; the goal run is the artifact's, byte-for-byte.
- **D2 shown = derived.** A derived rule's shown text is rendered from the `Rule` binding the
  engine returned, through the one existing grammar: `presentClinicalAdvice` over a one-rule
  `clinical_answer(<document>,[Rule],<marker>)` adapter, accepting ONLY `structured` output
  with exactly one item — the passage fallback never renders. `src/questions/advice.ts` stays
  byte-frozen (`clinical-records` T9), which is why the grammar is reached through its public
  entry rather than re-exported. Cited clauses = the distinct `line(L)` values in the returned
  `Proof`.
- **D3 binding.** On the real image, an overlay that erases one cited clause of a selected rule
  makes THAT rule `not-derived` while the other selected rules still derive, and the shown set
  changes through the shipped service — never through the engine alone. RED under a mutant
  service that renders the artifact's rule without querying.
- **D4 fail closed per rule.** `failure` → `not-derived`, `limit` and `error` → their own
  states; none renders as an answer. An `answered` selection whose rules all fail to derive
  shows that, never a recommendation.
- **D5 one engine queue.** Every engine call — built-in query, proof, intake derivation — runs
  after the previous one SETTLED, aborted proofs included (consultant P5). An intake run owns a
  token claimed before judgment and rechecked before each derivation and each state write; a
  newer submission supersedes it.

## Rulings during the build

MAIN rulings on questions the teammates raised, or on evidence the build produced. Each binds
the predicate it names.

- V1 digest = sha256 hex of `JSON.stringify(artifact minus digest)`, emitted key order, compact,
  no trailing LF.
