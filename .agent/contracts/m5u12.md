# u12 — scope-aware projection

Tier: `kernel`. The projection decides what the graph MEANS: a dropped negation renders a
recommendation as its clinical inverse. Nothing downstream re-checks it — u13 grades the SHOWN
conjunction against the final renderer, but it can only show what the projection hands it.

Dispatch: `prod-model` + `orc-proj` — scope-aware projection against a committed review suite
and an independent asset-derived oracle; MAIN rules and wires the gate.

## What ships

`src/graph/model.ts` reads u11's scope data and preserves it through the concept projection.
Today it drops both fields on the floor: `parseEdge` (`:182-194`) ALLOWLISTS edge fields, so
`edge.scope` never survives parsing, and `parseSemanticGraph` (`:220`) ignores the top-level
`scopes` table entirely. Teaching the reader to parse them is this unit's first move.

u11 shipped (commit `32c6a84`, contract `.agent/contracts/m5u11.md`):

- `schemaVersion` **2**; top-level `scopes` array of **1,263** records sorted by `id`, each
  `{ id, chain, operator, document, sentence, reference }`.
- `chain` = the resolved outer context, **ORDERED OUTERMOST FIRST**. Depth maxes at 2; the root
  atom `actual` and an unresolved rule variable each terminate a chain as a literal element.
- `operator` = one of `-` `should` `may` `can` `must`. Census: `should` 857, `-` 156, `may` 156,
  `can` 85, `must` 9.
- `edge.scope` = an INDEX into `scopes`, present on operator-bearing edges and absent otherwise.
  17,667 edges carry one; all 1,193 operator edges do; 0 indexes are unresolvable.
- **7 scope records are unreferenced and that is legal** — user ruling, u11 S3. 71 operator
  contexts carry no edge at all (64 negation, 7 `can`); see `.agent/deferred.md`. The
  projection must not assume every record is reachable from an edge.

## Predicates

- **P1 parse.** `parseSemanticGraph` accepts the v2 asset's `scopes` table and `parseEdge`
  preserves `edge.scope`, both validated at the boundary the way every other field is: a
  malformed record, an out-of-range index or a non-integer scope is a `GraphDataError` naming
  the field. An unreferenced record is NOT an error.
- **P2 ordered scope survives projection.** Every projected edge preserves its relation AND its
  ordered scope. Grouping and dedup key on the scope sequence, so two occurrences that differ
  only in scope order stay distinct groups rather than collapsing.
- **P3 the six in-scope review reds go GREEN.** `tests/graph-semantics.review.test.ts` merges
  into the primary tree from branch `wt/rev-sem-2` and the six named below pass.
- **P4 the two accepted-open reds are measured, then FIXED.** User ruling: u12 closes S9 and
  S13+ rather than shipping them red or xfailed, because `binding:check` fails the gate on any
  red case in the run (`tools/binding-check.mjs:267`) and every other disposition — xfail, a
  split suite, leaving them on the branch — stops executing the defect. P4 records the
  measurement at base; P7 and P8 carry the fixes.
- **P5 no `operator-context` node in the concept view.** The user ruling holds after the
  change: scope rides the edges. `CONCEPT_NODE_KINDS` gains no member.
- **P6 fail-closed at the boundary, not silently in the projection.** Whatever the projection
  cannot represent is refused where it is read, never dropped without a trace — that is the
  shape S13+ describes, and u12 must not add a NEW silent drop of its own.
- **P7 S9 — the headline counts what it names.** The concept view's headline calls its node
  total "concepts/actions" while value/attribute nodes sit inside it, and
  `hiddenTechnicalNodes`/`hiddenTechnicalEdges` are described as parser and provenance
  scaffolding while counting dropped negation operators too. Both counts must name their real
  membership, in `en.ts` AND `ja.ts` (key parity is graded), and the numbers must be derived
  from the model rather than restated. The graph's look is open to change by user ruling; every
  other accepted surface is not.
- **P8 S13+ — predicate-role validity is refused at the boundary.** `parseEdge` refuses an edge
  whose source violates its predicate's role rule (an argument edge whose source is not an
  event), naming the field, instead of letting the projection drop it silently. The rule is
  derived from the schema, and the SHIPPED asset must still parse with ZERO rejections: if a
  real corpus edge is role-invalid, that is a producer defect to REPORT, never a reason to
  loosen the validator.

**MAIN ruling on the `orc-proj` P3 objection — the first two cases STAND.** The oracle reports
them as grading the wrong surface: they scan every visible node and edge label for `/should/`,
`/not/`, `/may/`, `/30/`, which a token landing anywhere would satisfy, while scope is supposed
to be its own ordered channel. The assertion is WEAK, not wrong. `.agent/contracts/m5u8.md:90-97`
declares the view-model edge as `relation` (the relation label alone), `scope` (ordered;
negation and modality ride here) and `label` = **exactly relation + ordered scope** when shown,
so a shown label legitimately carries those tokens and the case is a NECESSARY condition on the
shipped view. The SUFFICIENT condition is m5u8's own wording, and the shown-edge conjunction is
graded whole against the FINAL renderer at u13 (user ruling, `.agent/spec.md` MAIN line). u12
must therefore satisfy BOTH halves: the structured `scope` array populated per edge, AND the
label composed as exactly relation + ordered scope — passing the case by writing tokens into a
label while leaving `scope` empty would satisfy the suite and breach the contract.

## Grading

`pnpm gate` rc 0 with the merged review suite in the tree. The six in-scope cases join
`binding:check`'s declared inventory — unlike u11's `data`-tier cases, these hold up the
meaning ruling, which is exactly what a declared register is for.

**MAIN ruling — the register is a THIRD table, `MEANING`.** `REQUIRED` is the answer-path roll
call, where every row names the part of the non-negotiable it holds up; a projection case holds
up the meaning ruling instead, and filing it there dilutes exactly the register the user split
`LIFECYCLE` out of. `LIFECYCLE` is narrower still — claims the view makes about a run settling.
`MEANING` therefore declares ALL NINE review cases across four `why` rows naming the same
suite, gets its own `gradeTable` call, its own `the MEANING table emptied` `requireFiring`
control and its own count in the success line. Wiring `tools/binding-check.mjs`; documented in
`.claude/rules/gate.md` as a bullet plus a `Firing inputs` row.

## Handoff to u13

u12 carries ordered scope as `SemanticGraphEdge.scopeOperators` — a model-side name, because
`edge.scope` is already the asset's numeric index into the `scopes` table and the two cannot
share a field. `m5u8.md:90-97` declares the renderer-neutral `EdgeView.scope`; no `EdgeView`
type exists in the tree yet, so u13 both creates it and maps `scopeOperators` → `scope`, with
`label` composed as exactly relation + ordered scope.
