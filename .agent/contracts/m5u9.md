# u9 — renderer restyle · kernel

Implements u8's ruling. Depends u8.
Split seam: the `canvas.ts` restyle ↔ the committed conformance probe.

## What shipped

`src/graph/canvas.ts`, six changes, each measured below:

1. **`curve-style: bezier`.** Cytoscape offsets each parallel edge's control point by its
   index within the node pair; `straight` collapsed every such edge onto one stroke. R1.
2. **`text-wrap: wrap` at 108 px**, replacing `ellipsis` at 96 px. R7.
3. **`text-outline-width: 2` in each node's own colour.** A wrapped label is wider than its
   54 px node, and the overflow was near-white text on a near-white canvas: `nonopioid
   therapy` read as `onopioid thera`, losing a character at each end with nothing on screen to
   say so. This was the dominant legibility defect on the bounded view and no counter could
   see it — the renderer draws the whole string, it is simply invisible.
4. **`autounselectify: true`.** Cytoscape's built-in stylesheet paints anything `:selected`
   `#0169D9` and a tap selects whatever it hit, so tapping a plain edge repainted it in the
   highlight's own register while the proof said nothing. R3.
5. **A fit floor.** `MIN_FIT_ZOOM = 11 / LABEL_PX`; below it the view pans instead of
   shrinking. R5.
6. **One layout for every view**, fcose with `nodeDimensionsIncludeLabels`, spacing scaled by
   node count, and the answer's subject pinned at the origin.

`elementsOf` no longer drops self-relations. The comment justifying that filter cited a
`curve-style: straight` limitation that no longer holds; the graph carries **0 self-edges of
20,964**, so the removal is a no-op today and stops silently dropping a class u11/u12 could
introduce.

## Measured — the layout ruling

The u8 spike ran fcose on every fixture. The shipped adapter did not: a view WITH a proof
highlight took a `concentric` branch, so **the spike's answer-view numbers never described the
answer view** — the one surface every question produces. Measured on the same 12 views at
1152x558, median:

| layout | crossings | panning | label overlaps |
| --- | --- | --- | --- |
| `concentric` (shipped) | 156.5 | 0.94 x 1.88 canvases | 0 |
| fcose | 56 | 0.90 x 1.40 | 0 |
| fcose + subject pinned at origin | 56.5 | 0.84 x 1.22 | 0 |

Pinning costs nothing and keeps concentric's whole reading — the answer's subject at the
centre — so `concentric` is gone.

Spacing then had no single setting. At the model's `DEFAULT_ANSWER_GRAPH_LIMIT` the tight end
reads best; at `DEFAULT_NEIGHBOR_LIMIT` it leaves the bounded hub unreadable:

| spacing | answer pan | bounded-hub label overlaps | bounded-hub crossings |
| --- | --- | --- | --- |
| 9000 / 100 / 90 | 0.84 x 1.22 | 64-86 | ~1,300 |
| 20000 / 180 / 120 | 1.05 x 1.71 | 37 | 1,737 |
| interpolated on node count | 0.81 x 1.27 | 14-29 | ~1,400 |

The interpolation beats both endpoints, and its two anchors are the model's own limits rather
than tuned constants. fcose is stochastic (`randomize: true`), so overlap counts move run to
run — every R1-R7 rule is layout-independent or one-sided, which is what keeps the check
stable while these numbers drift.

## Measured — the shipped result

`pnpm graph:check`, 14 fixtures x 2 viewports:

```
                     nodes/edges   label    overlaps  crossings   panning      settle
desktop 12 answer      13-27/14-40  11.00 px        0       54.5  0.81 x 1.27   33 ms
desktop worst-bounded      80/156   11.00 px       20      1,412  0.96 x 1.56  123 ms
desktop parallel           3/5      24.38 px        0          0  fits          —
mobile  12 answer      13-27/14-40  11.00 px        0       55.5  2.92 x 1.84   32 ms
mobile  worst-bounded      80/156   11.00 px       29      1,577  3.69 x 2.26  102 ms
```

Every view but the 3-node fixture settles exactly at the floor, so the floor is what sets the
label size everywhere — and 2.92 x 1.84 canvases of panning on a 296 px phone is what it
costs. Without it those same views land at 7.28 px.

## The probe

`tools/graph-probe/` + `tools/graph-check.mjs`, wired as `pnpm graph:check` and into
`pnpm release:check`. Out of `pnpm gate` on the `pnpm smoke` precedent: it needs a real
browser.

It mounts the SHIPPED `mountGraphCanvas`, never a restatement of its stylesheet, and reads
Cytoscape back off `container._cyreg.cy` — the adapter exposes no instance, and the contract
stays renderer-neutral while its probe cannot. Fixtures are derived, not committed: the cited
documents come from the bag through `answerDocuments`, the sentences and lines from each
provenance chunk, exactly as `tests/graph-live.test.ts` builds them.

A green run proves it graded something: the summary's own counts are required non-zero, and
`labelsMeasured` must equal the node count, so a culled or unmeasured label cannot pass as
whole.

## Not in this unit

The canvas hardcodes light-theme hex. It reads acceptably under the dark theme — node fills
and white labels gain contrast, and the edge-label pill stays legible — but it does not
follow the theme tokens. Making it follow them means passing the theme through
`mountGraphCanvas`, which R6 pins, so it belongs to u10's integration — where its theme half
shipped it, canvas colours resolving from `app.css` tokens under `graph:check` `palette` +
`theme`.
