# acceptance contract — M1.u4 question catalog + live answer service

Tier = `kernel`, flag = `oracle`. MAIN authors every code file in the primary tree. This
contract is the single decision surface: the red suite, the differential checks, the
review checklists and every divergence ruling decide against it, never against MAIN's
code.

Source clause (`.agent/roadmap.md`, M1 u4):
> Six ID-only catalog entries — the four exported projections plus repo-authored
> category-B and evidence-type-3 goals — compiled goals, canonical sorted result
> serializer, generic guideline-ID humanizer.
> Accept: all six IDs execute live through u2/u3; category-A reproduces its committed
> answer bytes and the other three are canonical value-equal to theirs; an injected
> overlay clause changes the displayed service result; a forbidden-import check fails on
> any production import of `queries/answers`; unsupported IDs and free text reject.

The u2 and u3 contracts (`.scratch/contract-m1u2.md`, `.scratch/contract-m1u3.md`) stay in
force in full. Their `D`, `P` and `I` items are inherited, not restated. u4 adds no
unbudgeted surface and changes no engine module.

## P — testable predicates

`MUST` = failure is a defect. Every red test, review row and differential check binds to
one id.

### P1 catalog
- P1.1 The catalog MUST expose exactly six entries, each keyed by a stable string id. No
  entry may be reachable except through its id.
- P1.2 An unknown id MUST reject with a typed error and MUST NOT reach the engine.
- P1.3 Free text MUST reject with the same typed rejection as an unknown id. No input path
  may compile caller text into a goal.
- P1.4 Every entry MUST carry its compiled goal and its projection. Neither may be derived
  at call time from a display string.
- P1.5 The four exported goals MUST be byte-equal to the `goal/1` argument in the bag's
  `queries/pl/<id>.pl`, and that equality MUST hold by construction because the generator
  reads the bag. [D1, D4]
- P1.6 Each entry MUST record its provenance — bag-exported or repo-authored — because the
  UI has to be able to say which. [roadmap: honest framing]
- P1.7 The generator MUST read the bag in memory through the verified BagIt path and MUST
  never read an extracted copy. [`.agent/memory.md`: verify = `pnpm kb:build`, never extracts]
- P1.8 The atom substitution producing each repo-authored goal MUST replace exactly one
  quoted-atom token, and MUST fail closed on zero or more than one. [D3]
- P1.9 Generation MUST be deterministic: two runs from the same bag MUST emit byte-identical
  catalog output. [u1 precedent: `kb:reproduce`]
- P1.10 A malformed, unexpected or mutated query clause MUST fail generation closed, never
  emit a silently wrong goal. [both spikes' `s.drift`]

### P2 answer service
- P2.1 Every catalog id MUST execute live through u2's `EngineClient` and u3's budget
  surface. No service path may run a goal without a validated `BudgetSpec`. [u3 P1.1, P6.2]
- P2.2 A service result MUST be derived from the live run alone. No committed answer
  fixture may be read, imported or reachable from production code. [roadmap accept]
- P2.3 The service MUST surface every u3 terminal state — each limit, cancellation, failure
  and error — without collapsing them into one "no answer" case. [u3 P2.*]
- P2.4 An honest zero-solution run MUST be distinguishable from a limit and from an error.
  [u3 P5.2]
- P2.5 An existence question — empty projection — MUST render yes/no, not an empty binding
  list. `recommendation-exists` MUST report yes from its 12 raw proofs. [both spikes]
- P2.6 The service MUST NOT call `JSON.stringify` on any engine value. [`.agent/memory.md`:
  `'$guideline_id'/5` re-enters at arity 1 with `ref([1])`; `1r3` serializes as `3r1`]
- P2.7 The service MUST project only the variables the entry's projection declares. An
  undeclared binding MUST NOT reach the serialized result.
- P2.8 The service MUST NOT expose `consult` as an answer path. [u3 D6: consult is
  unbudgeted and fails open]

### P3 serializer
- P3.1 Serialization MUST be canonical: the same solution set MUST produce identical bytes
  regardless of the order the engine yielded it in.
- P3.2 The sort MUST be a total order over decoded terms implementing SWI standard order —
  `Var < Number < Atom < String < Compound`, compounds by arity, then name, then arguments
  left to right. No two distinct solutions may compare equal. [D5]
- P3.3 `category-a-recommendations` MUST reproduce the committed `solutions([...])`
  substring byte for byte, compared against the bag's own file read at test time. [D6]
- P3.4 The other three exported ids MUST be canonical value-equal to their committed
  answers, each verdict reported separately, each divergence named exactly rather than
  tolerated.
- P3.5 Per-binding display text MUST come from the engine's own `term_string/3` output,
  never from JS templating. [u2 contract]
- P3.6 The serializer MUST wrap each solution as `sol([values])` and the set as
  `solutions([...])`, matching the bag's result grammar. [`m.answers`]

### P4 humanizer
- P4.1 The humanizer MUST be generic over guideline ids. No CDC-specific atom, prefix,
  document name or token gloss may appear in its logic. [D8]
- P4.2 An id it cannot parse MUST degrade to the raw id text, never to a fabricated label
  and never to a throw.
- P4.3 Humanized text MUST be presentation only. It MUST NOT feed back into any goal,
  comparison, sort key or serialized byte.

### P5 anti-hard-coding
- P5.1 An injected overlay clause MUST change the displayed service result, proven with the
  overlay observably absent beforehand. [roadmap accept; `.agent/memory.md`: schema
  predicates are static, so the overlay declares `dynamic/1` first; spike-src measured 7→8]
- P5.2 A production reach for `queries/answers` MUST fail the gate, proven by a committed
  negative control that introduces the reach. The check MUST catch a static import, a
  dynamic `import()` and an `fs` read alike. [D7]
- P5.3 No test may assert a constant it derived from the artifact under test. [u3 I]

### P6 gate
- P6.1 `rm -rf kb/generated && pnpm gate` MUST be rc 0 from committed state.
- P6.2 Every catalog id MUST have a committed live test against the real
  `kb/generated/kb.pvm`, not a stub.
- P6.3 Live tests MUST fail, not skip, when `kb/generated/` is absent. [u2 P5.5, u3 P7.3]
- P6.4 Catalog generation MUST run inside `pnpm kb:build`, adding no separate gate step.
  [D1: 0.631 ms integrated]

## I — invariant surfaces (spot-check even on a green run)

- 337, schema 1 and every solution count stay values read from the engine, never literals.
- The byte claim is proven against the bag's own file read at test time, never against a
  transcribed copy.
- The overlay probe proves the overlay was observably absent before it was asserted.
- A "canonical value-equal" verdict names its comparison; "both are non-empty" is a defect.
- The standard-order comparator is proven on a case where it disagrees with a byte sort,
  not only on the corpus where the two coincide.
- The forbidden-reach check is proven by a control that actually fails, not by an empty scan.

## G — gate identity

Decisive commands MAIN reruns before the unit closes:
1. `rm -rf kb/generated && pnpm gate` → rc 0.
2. `pnpm test` → all six ids green live against the real PVM.
3. Forbidden-reach negative control → gate fails on an introduced production reach for
   `queries/answers`, in all three reach forms.
4. `pnpm kb:reproduce` → catalog emission byte-identical across two forced builds.
5. Sibling-path scan → empty.

## Q — probe-corpus seed

Catalog: six ids exactly · unknown id · empty string · whitespace · an ACE sentence · a raw
Prolog goal · a goal-shaped string · an id differing by case · an id with a trailing period ·
`__proto__` and `constructor` as ids · a valid id reached through a computed property.

Generation: clean bag · a mutated `goal/1` argument · a missing query file · an extra query
file · a projection with an unexpected functor · a substitution atom appearing zero times ·
appearing twice · appearing as a substring of a longer atom (`'category-B-decision'`,
`'evidence-type-2-recommendation'`).

Serializer: the four exported result sets · the two authored result sets · an empty solution
set · a single solution · duplicate solutions · solutions differing only in argument order ·
a mixed-shape set where byte sort and standard order disagree (atom vs number vs compound,
compounds of differing arity, same arity differing name) · a solution carrying a rational ·
a solution carrying a variable.

Service: each of the six ids live · an id under an answer cap of 1 · under a wall-clock of
1 ms · under a depth of 1 · a cancelled run · a run against a poisoned engine · a run whose
overlay changes the result · a run after a hard reset restores 337.

Humanizer: `product`/`ref(N)` · `context`/`box(N)` · a non-CDC document id · an id with no
hyphens · sentence ordinal at 1 and at 25 · a non-empty dependency list · wrong arity ·
wrong functor · a non-atom document id.
