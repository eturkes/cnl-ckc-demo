# u14 — claim alignment

Tier: `kernel`. A false claim about the answer path is the one defect class this repo's
non-negotiable exists to prevent, and nothing downstream re-checks a sentence for TRUTH:
`copy:check` grades English sentence length and banned filler, and Japanese key parity — it
cannot tell a true sentence from a false one. The judgment is the deliverable.

Dispatch: `map-claims` + `orc-claims` — two independent adjudications of the 48-row claim set,
`orc-claims` blind to `map-claims`; MAIN ruled the 17 rows either pass flagged and wrote the
corrected prose.

## The defect

Three things a reader must be able to tell apart, and the shipped surfaces blur:

1. **A quotation** — bytes the guideline itself contains, carried through unchanged.
2. **A hypothetical premise** — the clinical context the DEMO supplies so a universally
   quantified guideline clause can apply. The KB does not assert it.
3. **A derived clause** — what the engine proved, live, from 1 and 2.

The answer path now genuinely derives (u1–u7), the ladder now shows premises as their own
deduplicated steps inside the existing rungs (u5), and the graph now carries scope on its edges
(u11–u13). Every claim string predates some part of that, so each one is either newly true,
newly false, or true-but-unreadable.

## What ships

Corrected strings on the surfaces that hold them TODAY:

- `src/i18n/en.ts` and its `src/i18n/ja.ts` twin — the `lede` plus the explanatory `TEXT`
  entries and the interpolated `PROSE` entries. i18n took this copy out of
  `ProvenanceLadder.svelte`; `src/demo/copy.ts` is licence data and is NOT a claim surface.
- `README.md` — the lede, `## What is included`, and any later section a sweep turns up.
- `src/questions/service.ts:1` — the answer-path header comment. It is read by agents, which
  makes it a durable claim even though no user sees it.

**Both locales move together.** `copy:check` grades key parity, so an English-only fix reddens
the gate; a Japanese string that keeps the old claim while English states the new one is the
worse failure, because nothing at all catches it.

## Method — u14 re-derives its own set

The string list is NOT frozen here on purpose: u13 rewrites the graph copy, so a list written
now grades the wrong surface. u14 opens by re-deriving the exact set from the live catalogs and
records it in this contract before changing a byte.

The sweep is mechanical and must be reported with its command and its rc:

```
/usr/bin/rg -n 'live|prove[nd]?|derive[sd]?|re-ran|re-proved|exact|unchanged|verbatim|quote|stored|fixture|hidden|only|every|all ' src/i18n/en.ts src/i18n/ja.ts README.md src/questions/service.ts
```

Every hit is then adjudicated into exactly one of four dispositions, and the count per
disposition is the deliverable:

| disposition | meaning |
|---|---|
| `true` | the sentence is accurate against the shipped surface; cite what makes it so |
| `false` | the sentence asserts something the tree does not do; rewrite it |
| `unreadable` | accurate but a reader cannot tell which of the three kinds it describes; disambiguate |
| `not a claim` | wording, not an assertion about behavior |

A `true` disposition needs its evidence the same way a `false` one does. A claim nobody can
re-derive is what u15 exists to catch, so u14 hands u15 the command per surviving claim.

## Predicates

- **A1 the set is re-derived, not inherited.** u14 reports the sweep command, its rc, the hit
  count, and the disposition of every hit. A hit left unadjudicated fails A1.
- **A2 the three kinds read as distinct, in BOTH locales.** A reader of either interface can
  tell a quotation from a hypothetical premise from a derived clause, on the surface where each
  appears.
- **A3 no surviving claim outruns the tree.** Every `true` and every rewritten string names the
  committed-state command or `file:line` that makes it so. That list is u15's input.
- **A4 the copy checks pass.** `copy:check` grades English at 20 words per instruction sentence
  and 25 per description, banned filler, and Japanese key parity. A rewrite that trips it is not
  done.
- **A5 the register holds.** Human-facing text stays ASD-STE100: imperative steps, one
  instruction per sentence, condition before command, simple tenses, active voice, definite
  modality, fixed terminology, no `simply` / `robust` / `seamlessly` / `leverage`.
- **A6 the accepted surfaces are untouched.** Copy LAYOUT is an accepted surface by user ruling
  — a change forcing a visual difference in the answer panel, ladder, combobox, theme or type
  stops and asks.

## Adjudication — two blind passes, then MAIN

Judgment is the deliverable here, so the set was adjudicated TWICE against the same 48-row
skeleton, each pass writing cells in place: `map-claims` (mapping pass) and `orc-claims`
(differential oracle, briefed never to read its peer's report). Both returned 48/48.

| pass | `true` | `false` | `unreadable` | `not a claim` |
|---|---|---|---|---|
| `map-claims` | 34 | 5 | 6 | 3 |
| `orc-claims` | 34 | 8 | 3 | 3 |
| **MAIN, ruled** | **28** | **10** | **7** | **3** |

They agreed on 36 rows and disputed 12; the union either flagged is 17. MAIN ruled every one of
those 17 and took the agreed disposition on the other 31 — two independent blind passes reaching
the same `true` is the strongest evidence available for a sentence nothing mechanical can grade.

**Every one of the 12 disputes was settled against code MAIN read itself, not by preferring a
pass.** Seven turned on a decisive fact — `SemanticGraph.svelte:313-316`, `model.ts:816-845`,
`reproduce.mjs:36-37`, `client.ts:50`, `client.ts:211` — and each of those seven went to the
agent that had flagged it. The remaining five (`A06 A09 A10 A22 A43`) were factually accurate
and ruled `unreadable` under this contract's own A2, which asks whether the three kinds read as
distinct, not whether the sentence is true.

The 17 corrections by surface: `en.ts` 10 of 27 hits, `README.md` 4 of 13, `service.ts` 3 of 6,
`ja.ts` 0 of 2. Eight of the ten `en.ts` rows are catalog keys and each moved with its `ja.ts`
twin; the other two (`A03`, `A27`) are file comments and have no twin.

**Two anchors `## Known anchors` names by hand fall outside the sweep, and both hold as written
— checked, not assumed:**

- `README.md:17` *"Explicit projection-loss and `unreviewed` disclosures."* Both halves are
  true and now match u12/u13's loss: `graphViewOmissions` and `graphRelationsTruncated` name
  the omitted rows AND the relation identities missing a scope variant, `graphHiddenScaffolding`
  names the source-detail totals, and `README.md:36` plus `reviewUnreviewed` carry the label.
- `src/i18n/en.ts` `proofPremiseOrigin` and its `ja.ts` twin say the same thing —
  *"The knowledge base does not state a premise, so a premise has no source line."* against
  *「知識ベースは前提を述べていないため、前提に出典の行はありません。」* This row was already
  correct and is what the other premise corrections were written to agree with.
