# Interface language

Two locales, `en` and `ja`. **The interface translates; the knowledge base does
not.** Question strings, ACE renderings, canonical Prolog values, document ids,
review labels and engine error messages are payload and ship in the language their
source is written in. The frame around an engine message translates —
`TEXT.runFailed(code, message)` — the message itself never does.

## The seam

- `src/i18n/en.ts` = the KEY SCHEMA. Four buckets: `INSTRUCTIONS` (≤20 words per
  sentence), `DESCRIPTIONS`, `LABELS`, `TEXT`. It also exports `Messages`, which
  widens every value to `string` ⇒ **a missing, extra or misnamed key in `ja.ts`
  is a `pnpm check` failure**, not a silent English fallback at run time.
- `src/i18n/ja.ts` = the same keys in Japanese, です・ます register. Terminology is
  fixed and reused: 知識ベース, コンパイル済み, 制御自然言語, 証明, 出典 (a
  citation), 原文 (the guideline's own prose), 節 (a clause), 概念/動作/属性 (the
  three graph node kinds), 関係 (an edge). Punctuation is fixed too: a label and its
  value are separated by an **ASCII `: `**, never `：` — nine strings already do it,
  and a lone fullwidth colon reads as a different kind of label.
- `src/i18n/locale.svelte.ts` = the `locale` rune plus `messages`, a **getter**.
  Exporting the resolved bundle would capture it once and freeze the UI in
  whichever language loaded first.

Consume it as `const t = $derived(messages.current)` in a `.svelte` script, or as
`const { TEXT } = messages.current` **inside a function body** in a plain `.ts`.
Never hoist `messages.current` to module scope.

## Why `TEXT` entries return whole sentences

Japanese reorders what English concatenates, and it has no plural agreement. A
shared `${count} ${noun}` helper therefore forces one language's word order onto
the other — `en.ts` keeps a private `plural()` and `ja.ts` has no equivalent,
because each Japanese entry writes its own counter (件, 行) directly.

**No string may be built by joining catalog fragments.** The two exceptions are
declared as explicit before/after pairs and exist only because a returned string
cannot carry a `<code>` element: `LABELS.graphSelected{Before,After}` and
`TEXT.graphHighlightOrigin{Before,After}`. Both halves of the latter take the
count, because English puts it before the document id and Japanese after.

## Fonts

`BIZ UDPGothic` (`@fontsource`, **not** `@fontsource-variable`) ships as two
static weights, 400 and 700 — 1,319,288 B + 1,335,452 B, the monolithic `japanese`
subset. Both ship because this UI leans on weight 600-700 and synthetic bold
smears CJK strokes at 0.78rem, which is the exact legibility a Universal Design
face was chosen for. `unicode-range` keeps both off an English visitor's download
entirely.

Rejected: the 30-slice `unicode-range` partition (401 KB for a 160-character
vocabulary, 30 `@font-face` rows, and tofu on any glyph outside the pinned
slices), and a build-time subset (≈25 KB, but a new dependency, a new gate step
and a generated binary).

**Nothing in the header may carry a Japanese glyph.** `LABELS.languageSwitch` is
ASCII in BOTH locales — `日本語` would make an English visitor fetch 1.3 MB to
render three characters. `tests/i18n.dom.test.ts` holds that invariant.

## Gate

- `copy:check` grades `en.ts` on sentence length and banned filler, and grades
  `ja.ts` on **parity alone**: every English key present, every value actually
  rewritten. The word limits do not port — Japanese has no word spaces, so
  `words()` would score every sentence as one and pass anything. Parity compares
  SOURCE SLICES, which is what reaches `TEXT`'s function entries. It ships three firing
  inputs, one per grader, and reads `en.ts` as the Japanese catalog for the parity one
  (`.claude/rules/gate.md` `Firing inputs`).
- `presentation:check` `FACES` rows carry a per-row `scope` and a filename
  `marker`, because the Japanese face is not a `-wght-` variable file. 8 faces,
  4 licences byte-equal.
- `tests/i18n.dom.test.ts` reads RENDERED text, never the catalog. A locale seam
  passes key parity and still ships English; only rendered output decides that. It
  also holds WCAG 2.5.3 for both header toggles: an `aria-label` must contain the
  visible label, case-insensitively, in both locales and both states. axe's
  `label-content-name-mismatch` is experimental and off by default, so nothing else
  sees it.
- `browser:check` owns the font budget, because only a browser decides it: before
  the toggle `document.fonts` must report the two faces `declared` and none
  `loaded` with no `biz-udpgothic` request in the server log, and after it the face
  must be `loaded` and requested. Renaming the expected asset fails it with
  `Japanese rendered without the Japanese face` — the mutation is the firing input this
  lane still owes, and it is a `.agent/deferred.md` row until the lane runs it
  itself.
