# Interface language

Two locales, `en` and `ja`. **The interface translates; the knowledge base does
not.** Question strings, ACE renderings, canonical Prolog values, document ids,
review labels and engine error messages are payload and ship in the language their
source is written in. The frame around an engine message translates —
`TEXT.runFailed(code, message)` — the message itself never does.

## The seam

- `src/i18n/en.ts` = the KEY SCHEMA. Four buckets: `INSTRUCTIONS` (≤20 words per
  sentence), `DESCRIPTIONS`, `LABELS`, `TEXT`. It also exports `Messages`, which
  widens every value to `string` ⇒ **a missing or misnamed key in `ja.ts`
  is a `pnpm check` failure**, not a silent English fallback at run time. `ja.ts` reaches
  `Messages` through four bucket identifiers rather than one object literal, so an EXTRA key
  stays structurally assignable and `copy:check` key parity is what names it
  (`copy-check.mjs`, `not a key of en.ts`).
- `src/i18n/ja.ts` = the same keys in Japanese, です・ます register. Terminology is
  fixed and reused: 知識ベース, コンパイル済み, 制御自然言語, 証明, 出典 (a
  citation), 原文 (the guideline's own prose), 節 (a clause), 概念/動作/属性 (the
  three graph node kinds), 関係 (an edge). Punctuation is fixed too: a label and its
  value are separated by an **ASCII `: `**, never `：` — nine strings already do it,
  and a lone fullwidth colon reads as a different kind of label.
- `src/i18n/locale.svelte.ts` = the `locale` rune plus `messages`, a **getter**.
  Exporting the resolved bundle would capture it once and freeze the UI in
  whichever language loaded first.

Consume it as `const t = $derived(messages.current)` in a `.svelte` script, or as
`const { TEXT } = messages.current` **inside a function body** in a plain `.ts`.
Never hoist `messages.current` to module scope.

## Why `TEXT` entries return whole sentences

Japanese reorders what English concatenates, and it has no plural agreement. A
shared `${count} ${noun}` helper therefore forces one language's word order onto
the other — `en.ts` keeps a private `plural()` and `ja.ts` has no equivalent,
because each Japanese entry writes its own counter (件, 行) directly.

**No string may be built by joining catalog fragments.** The two exceptions are
declared as explicit before/after pairs and exist only because a returned string
cannot carry a `<code>` element: `LABELS.graphSelected{Before,After}` and
`TEXT.graphHighlightOrigin{Before,After}`. Both halves of the latter take the
count, because English puts it before the document id and Japanese after.
`copy:check` refuses two catalog references a component renders side by side or joins with
`+` or one template literal, unless they are a declared pair or the first ends a sentence in
both locales — two whole sentences keep each language's order.

## Fonts

`BIZ UDPGothic` (`@fontsource`, **not** `@fontsource-variable`) ships as two
static weights, 400 and 700, each a committed SUBSET of the package's monolithic
`japanese` file: `src/fonts/*.subset.woff2`, cut by `pnpm font:subset`. Both weights
ship because this UI leans on weight 600-700 and synthetic bold smears CJK strokes
at 0.78rem, which is the exact legibility a Universal Design face was chosen for.
`unicode-range` keeps both off an English visitor's download entirely.

- The subset = every code point `src/i18n/ja.ts` uses inside the face's
  `unicode-range` + `SAFETY` (kana, CJK punctuation, fullwidth ASCII, so typed
  Japanese keeps the face for all but uncatalogued kanji) + `AUTOFIT`, each limited
  to what the original maps (`tools/fonts.mjs`).
- **`AUTOFIT` is load-bearing.** FreeType's autofitter sizes CJK blue zones from 150
  reference ideographs (`afblue.dat` `AF_BLUE_STRING_CJK_*`, `afscript.h` 田 囗), and
  Chromium on Linux hints with it. Without them every kana rasterizes a few pixels
  off the original; with them the Japanese UI renders pixel-identical.
- **A `ja.ts` edit that adds or drops a code point needs `pnpm font:subset`.**
  `presentation:check` re-derives the set from the catalog and refuses a subset that
  lacks or exceeds it, by code point. The cut is byte-deterministic for a fixed
  `subset-font` + `harfbuzzjs`.
- No Reserved Font Name in the OFL text, so the subset keeps the family name.

Rejected: the 30-slice `unicode-range` partition (401 KB for a 160-character
vocabulary, 30 `@font-face` rows, and tofu on any glyph outside the pinned slices).

**Nothing in the header may carry a Japanese glyph.** `LABELS.languageSwitch` is
ASCII in BOTH locales — `日本語` would make an English visitor fetch the Japanese
face to render three characters. `tests/i18n.dom.test.ts` holds that invariant.

## Gate

- `copy:check` grades `en.ts` and every component's literal prose on sentence length and
  banned filler. It grades `ja.ts` on parity (every English key present, every value
  rewritten) and on register (`.agent/contracts/mnt-d3.md`). The word limits do not port —
  Japanese has no word spaces — so register has its own unit: one character, with an ASCII
  word run or a `${…}` counting one. A sentence runs up to and including `。！？`; an
  unterminated run is a label, which keeps dictionary form. Parity and register compare SOURCE
  SLICES, which is what reaches `TEXT`'s function entries. Every grader ships its own firing
  input (`.claude/rules/gate.md` `Firing inputs`).
  - J1: a sentence ≤ 40 units in `INSTRUCTIONS`, ≤ 60 elsewhere.
  - J2: a key whose English names a term above carries its fixed Japanese term.
  - J3: a sentence ending in hiragana ends in a です・ます form; `はい`/`いいえ` are exempt.
  - J4: no `：`.
- `presentation:check` `FACES` rows carry a per-row `scope` and a filename
  `marker`, because the Japanese face is not a `-wght-` variable file; a shipped
  subset grades as the package face it was cut from. 8 faces, 4 licences byte-equal,
  2 subsets exact to the catalog.
- `tests/i18n.dom.test.ts` reads RENDERED text, never the catalog. A locale seam
  passes key parity and still ships English; only rendered output decides that. It
  also holds WCAG 2.5.3 for both header toggles: an `aria-label` must contain the
  visible label, case-insensitively, in both locales and both states. axe's
  `label-content-name-mismatch` is experimental and off by default, so nothing else
  sees it.
- `browser:check` owns the font budget, because only a browser decides it: before
  the toggle `document.fonts` must report the two faces `declared` and none
  `loaded` with no `biz-udpgothic` request in the server log, and after it the face
  must be `loaded` and requested. The lane runs its own firing input: a copy of the build
  with the Japanese `woff2` files renamed must be refused by the same face grader.
